# git-secret-guard: project notes

Bash tooling (no Python/Node): a git config hook (`hook.git-secret-guard.*`) runs trufflehog and betterleaks on the lines each commit adds. Issues live in GitHub LightspeedDMS/git-secret-guard (epics #1, #8). Behaviour is in `README.md` and `docs/{install,platforms,scan,exemptions,doctor}.md`; read the matching doc before changing behaviour. Each doc ends with **Maintainer notes** (internals, function and test names). This file holds only the rules and the invariants a "simplification" breaks.

## Layout

- `hooks/secret-scan`: the hook git runs; `<share>` = two levels above its resolved path, settings in `<share>/settings`. Hook libs: `lib/common.sh`, `lib/extract.{sh,awk}`, `lib/exempt.sh` (doctor reuses it), `lib/report.sh`, `lib/scanners/{trufflehog,betterleaks}.sh`, `lib/betterleaks-rule.toml`, `lib/run-scanner.sh`, `lib/proc.sh`.
- `bin/git-secret-guard`: the CLI (help in `lib/usage.md`; ends with `main "$@"; exit` so bash never reads a file `install` just replaced). CLI-only libs: `lib/{state,tools,hookspath,install,install_tools,uninstall,status,timer,launchd,doctor,doctor_repos,doctor_findings,brew}.sh`; the hook never loads them (`test_the_hook_never_loads_the_install_time_libraries`, `test_the_hook_never_loads_the_doctor_and_timer_libraries`).
- Tests: `tests/run.sh [FILE]`, harness `tests/lib.sh`, stand-ins `tests/stubs/`, helpers `tests/lifecycle.sh` (`lc_begin`, `gsg`) and `tests/doctor.sh` (`dr_begin`, `dr_repo`, `deep_path`), `tests/coverage.sh`; container runs in `tests/platform/` (not in `run.sh`). CI: `.github/workflows/tests.yml` (Ubuntu head vs base compare; on Windows the whole suite plus a clean-machine install/leak/uninstall job).
- Windows (Git for Windows) is first class: front ends `bin/gsg-bash.cmd`, `bin/git-secret-guard.cmd`, `tests/run.cmd`; `tests/test_windows.sh` fakes `uname` around the real libs, so the Windows branches also run on Linux and macOS; `tests/windows-skips.list` names what cannot apply. The Windows suites themselves do not run on a Mac (only CI runs them).

## Hard rules

- **Test isolation.** Each test file runs in `~/.tmp/git-secret-guard-tests.XXXXXX`: scratch `HOME`, `GIT_CONFIG_GLOBAL=<scratch>`, `GIT_CONFIG_NOSYSTEM=1`, `env -i`. The real `~/.gitconfig` sets `core.hooksPath=~/.config/git/hooks`: it must never apply, and nothing under `~/.config/git/` is ever modified. `PYTHONUSERBASE` points at the real `~/.local` (pre-commit is a `pip --user` install).
- **Fake secrets** are built at runtime (`fake_aws_key`, `fake_github_token`, `fake_aws_secret`), never printed; leak tests assert a marker is absent with `no_leak`. `tests/test_quality.sh` scans the tree with the real tools (`..._KEY=<40 hex>` trips betterleaks' `generic-api-key`).
- **Never dump the environment** in a probe hook (`env` once printed real API keys); log only `GIT_*` under `env -i`.
- **No real `brew` or `systemctl` in lifecycle tests**: `lc_begin` puts recording stand-ins first on every lifecycle `PATH`. The only real `systemctl` call is the read-only `systemctl show cidx-server` in `service_prepare` (`tests/lib.sh`, RHEL host service emulation, skips when unavailable).
- **Tool paths come only from the settings file.** `load_settings` unsets every settings key (and the old `GITLEAKS_*`) before sourcing; the hook checks the five tool paths with `tool_unusable` (else block, "nothing was scanned"); on Windows the settings hold `TASKKILL_BIN` instead of `SETSID_BIN`, and `JQ_BIN` is a wrapper in the share dir. Only `lib/install.sh` and `lib/brew.sh` may `type -P` (`test_the_hook_never_looks_tools_up_on_PATH`, `test_systemctl_is_looked_up_only_in_lib_install_sh`, `test_launchctl_is_looked_up_only_in_lib_install_sh`). bash (Linux shebang), git, awk, sed, coreutils do resolve via `PATH`; child scripts run under `"$BASH"` (docs/scan.md#how-it-works).
- **Settings** are generated by `install_write_settings` (`printf %q`; the hook sources them) on every install; `write_settings` in `tests/lib.sh` writes the same keys for hook suites.

## git

- **Config hooks need git >= 2.54.** RHEL host: `/usr/local/bin/git` 2.56; `/usr/bin/git` 2.52 silently ignores `hook.<name>.*`. Tests drive `GIT` (`GSG_TEST_GIT`; default `/usr/local/bin/git`, `/usr/bin/git` on macOS, the one on `PATH` on Windows). Config hooks run before the hookdir hook, both run, either failing blocks, whatever `core.hooksPath` says.
- git 2.56 output formats and exit codes the code relies on: docs/doctor.md#maintainer-notes (`git hook list`, `-z` layouts), docs/install.md#maintainer-notes (`git config` exit codes).

## Invariants: what breaks if you "simplify"

- **Scanner semantics are pinned per version** (trufflehog 3.99.2 exit 0 on unreadable input, `chunks >= 1`; betterleaks `--exit-code 42`, `WRN skipping` = error, validation never passed): docs/scan.md#maintainer-notes, `tests/test_real.sh`. Offline tests use a dead proxy (`HTTPS_PROXY=http://127.0.0.1:9`) so a fake credential is `unknown`; one online test skips offline.
- **A commit cannot mute itself**: explicit `--config`/`--gitleaks-ignore-path` always; root `.gitleaksignore`/`.betterleaksignore` renamed `<name>.gsg-committed` (`betterleaks_stage_tree`); exemptions read from HEAD only (`exempt_head_blob`, modes 100644/100755, a symlink blocks).
- **Lone AWS key ID**: our rule `aws-access-key-id` always runs, a second `--enable-rule` run when HEAD has a config (`test_real_a_lone_aws_key_id_under_a_skipped_path_passes_with_and_without_a_repo_config`, docs/scan.md#limits).
- **Built-in-rules status by behaviour, never by parsing TOML** (`betterleaks_config_preflight`: betterleaks exit 42 / 0 / other = on / warn / block, returns 0 / 2 / 1); a relative `[extend] path` fails by running from an empty cwd (`test_real_every_spelling_of_extend_path_is_refused`; an absolute path to an existing file still loads, a documented residual). Don't reintroduce awk/regex TOML detectors (docs/exemptions.md#maintainer-notes).
- **Extraction**: sparse scan files, never count scan-tree lines (`test_a_missing_or_garbage_counts_file_blocks_and_never_reports_zero`); fixed diff flags plus `--attr-source=<empty tree>`, `core.attributesFile=/dev/null`, `core.bigFileThreshold=100g` (`4095m` on Windows; add new keys to `tests/test_inherited_config.sh`); the hook unsets the four `GIT_*_PATHSPECS` and exports `GIT_NO_REPLACE_OBJECTS=1`.
- **Pathspecs** `:(exclude,top,glob)<p>`: `top` is required; excludes cannot be re-included, so `exempt_extract_tree` runs two diffs; catch-alls are judged by git itself (`scan_ignore_scope`, `_warn_if_union_covers_tree`).
- **Signals**: scanners and the reminder run in their own group (`lib/proc.sh`: `setsid` on Linux/macOS; on Windows no groups, a `/proc` walk for current Windows pids, then `taskkill /T /F`); `cleanup` kills, waits, then removes the work dir. Adapters keep `timeout --foreground`; doctor's git shim omits it (`test_a_timed_out_doctor_run_leaves_no_process_behind`).
- **Output**: a clean commit prints exemption notices, one pass line (`report_pass_line`, counts from `GSG_EXTRACT_COUNTS`) and the coverage reminder (`run_reminder`, only after `REMINDER_READY=1`; plain `"$BASH"` instead of `"$SETSID_BIN"` on Windows); the commit's own exit status never depends on the reminder.
- **Install order**: refusable checks before any lasting change (exceptions: the macOS `brew install bash` bootstrap, the set-and-remove config write probe, staging after brew when no GNU `timeout` exists); state before config; unset `core.hooksPath` last (`test_install_keeps_scanning_when_the_final_hooks_path_unset_fails`). Uninstall restores it first (`test_uninstall_restores_core_hooks_path_before_removing_the_hook_config`).
- **Scanner files**: ours (hash in `tools_placed`, `install_owns_file`) are replaced in place, anyone else's moved aside; every path is built with `tools_binary_name` (`.exe` on Windows); legacy gitleaks retired last, state rewritten before the restore (`test_an_interruption_after_the_restore_never_lets_the_rerun_delete_the_users_gitleaks`). Download override cannot skip verification (`test_the_base_url_override_cannot_skip_verification`). `/etc/os-release` is data, never sourced.
- **Doctor**: exit 1 only for a PROBLEM (WARNING/info never; `/usr/bin/git` 2.52 is permanently reachable on the RHEL host). Runs nothing a repository configures (`doctor_start`, `GIT_NO_LAZY_FETCH=1`, `core.fsmonitor=false` set after the `GIT_*` cleanup). Never prints a configured hook `command`/`event` value (`doctor_values_text`, `test_the_machine_section_never_prints_a_hook_config_value`); a disabling `enabled` value is shown; other values are cut with `trunc_text`. Discovery is one mechanism: `doctor_prune_args` (`-samefile`, default macOS run only, `Library` and `.Trash`) on both finds.
- **Findings record**: doctor's one write; data, never sourced; merged under the lock from a fresh read; machine records and checked repositories are refreshed, an unreached repository's record goes only when proven gone (`doctor_rec_proven_gone`); doctor never writes what it cannot read (`doctor_rec_check_size`); per-line checks stay linear. Lock = symlink to the holder pid (Git Bash `ln -s` refuses a missing target, so the lock sets `MSYS=winsymlinks:sys` inline), stale when the holder is dead or the link is over a minute old; uninstall takes it before changing anything.
- **macOS**: `/bin/bash` 3.2 cannot parse the libs; `brew_cli_bootstrap` re-execs with two loop bounds; every install refusal uses `brew_unchanged_text`; the hook blocks on a non-empty `GNUBIN_DIR` that is not an absolute directory (docs/platforms.md#maintainer-notes).
- **Windows**: bash and `find` say `/c/dir`, native git `C:/dir`, `cmd` `C:\dir`: compare in one form (`cygpath -m -l`), never test a native-git path with `/*`. A running script pins its directory (`install_copy_share`), the lock wait is bounded in seconds, and the work dir ignores a `TMPDIR` outside `HOME`. The rest, with test names: docs/platforms.md#maintainer-notes.

## Testing tricks

- **The hook never sees a fake `git` on `PATH`** (git prepends its exec-path). Inject `setsid`/`timeout` through settings (`use_stubs "SETSID_BIN=..."`). To break only the hook's probe repo, point `GIT_CONFIG_GLOBAL` (`set_env`) at a copy plus `[includeIf "gitdir:<TMPDIR>/"]`; to break doctor's git, a wrapper failing `git -C /` with 128. `GIT_TEST_ASSUME_DIFFERENT_OWNER=1` simulates `safe.directory`.
- **Stand-ins** report configured findings whatever the tree holds: clear `STUB_GL_FINDINGS` between steps, assert on `STUB_RECORD`. A stand-in that must be killed needs `exec sleep`.
- **Signals**: background jobs start with SIGINT ignored, so INT tests launch git with `env --default-signal=INT`. Never `pkill -f` a pattern that is in your own command line.
- **Stdin socket quirk**: with a socket on stdin, `env -i ... bash -c` reads `~/.bashrc` and changes `type -P` answers; tool-lookup helpers (`dr_which`, `lc_which`, `lc_first_git_dir`) redirect stdin from `/dev/null`.
- **Old git**: compute expectations from `/usr/bin/git --version`; a fake old git goes after the real one on `PATH`.
- **On a Mac** always run `tests/run.sh FILE` (it puts the brew bash and gnubin first; plain `bash tests/test_x.sh` gets BSD tools). Real-scanner tests read `~/.cache/git-secret-guard-test-tools` (`tests/fetch-test-tools.sh`; also the Windows default).

## Conventions

- Coded comments (`# ^ tag clause`), sparse; definition and lint: `awk -f tests/comment-rules.awk FILE`. Tags: hazard coupled security invariant external order why see perf todo; `why X, not Y; reason`; <= 160 chars, <= 3 coded lines in a row; no ` so `, ` but `, ` because `, ` which `, ` that `, ` then `, ` while `, `: `.
- `set -u`; check every return value; bounded loops; files under 1000 lines; shellcheck clean (info included) at `GSG_SHELLCHECK_PIN` 0.11.0 (other versions skip the gate). A local named like a sourced array (`lines`) trips SC2178/SC2128. Names must not be confusable (`INSTALL_TIMEOUT_BIN` is a path, not a duration).

## Correct as written: do not "fix"

- `wait "$!"` after `done < <(find ...)` or `mapfile < <(git ...)` returns the substituted command's status (bash 4.4+); a process substitution as stderr filter would race, hence pipe + `PIPESTATUS`.
- `${v%"${v##*[!/]}"}` trims all trailing slashes; `type -aP git` is valid; `A=0 B=""` alone on a line sets both; `${kv#*$'\n'}` needs its guard for valueless records.
- `doctor_unreadable` returning 1 means "not explained by permissions" (caller exits 2); `$key` in `doctor_repo_info` is the absolute common dir.
- A token in a remote URL path can appear in `EXEMPT_GIT_ERR` on the user's own stderr: accepted, it is the user's config shown to the user.
- `/proc/self/mountinfo` field 5 is the mount point, fstype follows the lone `-`; `awk -F: '$1 == "fpr" {print $10}'` is right for `gpg --with-colons`.
- `lib/extract.awk` writes nothing to stdout, so `2>&1 |` into the sanitizer swallows no extracted lines.
- Doctor's git shim omits `--foreground` on purpose; the hook adapters keep it on purpose.

# git-secret-guard: project notes

Bash tooling (no Python/Node). Issues live in GitHub LightspeedDMS/git-secret-guard: epic #1 (stories #2 scan, #3 exemptions, #4 lifecycle, #5 doctor, #6 Ubuntu, #7 migrate this machine) and epic #8 macOS (#9 Homebrew support, #10 bash 3.2 re-exec bug, #11 pass line). User-facing behaviour: `README.md` (overview) and `docs/{install,platforms,scan,exemptions,doctor}.md`; read the matching doc before changing behaviour. This file holds what the docs do not: why the code is shaped this way and what breaks if you "simplify" it.

## Layout

- `hooks/secret-scan`: what git runs as `hook.git-secret-guard.command`. Reads `<share>/settings`; `<share>` = two levels above the resolved script path.
- Hook libs: `lib/common.sh` (settings, `tool_unusable`, `strip_ansi`, `msg_words`, `trunc_text`, `first_message`), `lib/extract.sh` + `lib/extract.awk` (staged diff to scan tree), `lib/exempt.sh` (all in-repo exemptions and the betterleaks pre-flight; doctor reuses it), `lib/report.sh` (merge, print, pass line), `lib/scanners/{trufflehog,betterleaks}.sh` (`scan_<tool> <scan_dir> <abs out_dir>` writes `<tool>.rows` + `<tool>.errors`), `lib/betterleaks-rule.toml` (our `aws-access-key-id` rule, read by the adapter), `lib/run-scanner.sh` (started per scanner under `setsid`), `lib/proc.sh` (`proc_start_runner`/`proc_stop_group`: process groups via setsid on Linux/macOS, taskkill on Git for Windows).
- Windows (Git for Windows, from main's PR #18) and CI (`.github/workflows/tests.yml`, Ubuntu, head vs base log compare) were merged in; Windows is not exercised locally and has known gaps (the #15 reminder still calls `SETSID_BIN` directly; uninstall ignores `.exe` names).
- `bin/git-secret-guard`: the CLI (`install [--replace-hooks-path] [--with-timer]`, `uninstall [--remove-tools]`, `status`, `doctor [--roots DIR...]`, `version`, `help`; text in `lib/usage.md`). Symlinked into `~/.local/bin`; `GSG_ROOT` = two levels above its `realpath`. Ends with `main "$@"; exit` so bash never reads a file `install` just replaced.
- CLI-only libs: `lib/{state,tools,hookspath,install,install_tools,uninstall,status,timer,launchd,doctor,doctor_repos,doctor_findings}.sh` (`install_tools.sh` = tool ownership, plan, stage, commit, split out of `install.sh` to stay under 1000 lines; the `type -P` lookups stay in `install.sh`) and `lib/brew.sh` (bash 3.2 safe, sourced first). The hook never loads them (`test_the_hook_never_loads_the_install_time_libraries`, `test_the_hook_never_loads_the_doctor_and_timer_libraries`). `tools.lock` and `VERSION` are shipped data.
- Tests: `tests/run.sh [FILE]`; `tests/lib.sh` harness; `tests/stubs/{trufflehog,betterleaks}` stand-ins driven by `STUB_*`; `tests/fixtures/husky/h` = husky 9.1.7's real `h` (MIT, verbatim); `tests/lifecycle.sh`, `tests/doctor.sh` helpers; `tests/coverage.sh` xtrace line coverage (not `lib/extract.awk`); `tests/platform/` container runs (not in `tests/run.sh`).

## Hard rules

- **Test isolation.** Each test file runs in a sandbox under `~/.tmp/git-secret-guard-tests.XXXXXX`: scratch `HOME`, `GIT_CONFIG_GLOBAL=<scratch>`, `GIT_CONFIG_NOSYSTEM=1`, `env -i`; hook config is reset before each test. The real `~/.gitconfig` sets `core.hooksPath=~/.config/git/hooks` and must never apply; never modify anything under `~/.config/git/`. `PYTHONUSERBASE` points at the real `~/.local` (pre-commit is a `pip --user` install).
- **Fake secrets** are built at runtime from fragments (`fake_aws_key`, `fake_github_token`) or generated per call (`fake_aws_secret`), never printed; leak tests assert a unique marker is absent with `no_leak`. `tests/test_quality.sh` scans the tree with the real tools (a constant spelled `..._KEY=<40 hex>` trips betterleaks' generic-api-key rule).
- **Never dump the environment** in a probe hook (`env` once printed real API keys into a session); log only `GIT_*` under `env -i`.
- **Never run real `brew` or reach the real `systemctl`** from tests; `lc_begin` puts recording stand-ins first on every lifecycle `PATH`.
- **Tool paths come only from the settings file.** `load_settings` unsets `TRUFFLEHOG_BIN BETTERLEAKS_BIN JQ_BIN SETSID_BIN TASKKILL_BIN TIMEOUT_BIN SYSTEMCTL_BIN LAUNCHCTL_BIN BASH_BIN GNUBIN_DIR SCAN_TIMEOUT_SECONDS DOCTOR_TIMEOUT_SECONDS TRUFFLEHOG_VERSION BETTERLEAKS_VERSION` and the previous build's `GITLEAKS_BIN GITLEAKS_VERSION` before sourcing, so nothing inherited fills a gap. The hook validates the five tool paths with `tool_unusable` (absolute + executable, else block "nothing was scanned"). Only `lib/install.sh` may `type -P` (`test_the_hook_never_looks_tools_up_on_PATH`, `test_systemctl_is_looked_up_only_in_lib_install_sh`, `test_launchctl_is_looked_up_only_in_lib_install_sh`). `bash` (`#!/usr/bin/env bash`, deliberately unpinned), `git`, awk, sed and coreutils DO resolve via `PATH` (`test_the_docs_do_not_claim_the_hook_has_no_PATH_lookup`).
- **Settings** are generated by `install_write_settings` (`printf %q`; the hook sources them) on every install. `write_settings` in `tests/lib.sh` writes the same keys for hook suites (`TEST_SETSID`/`TEST_TIMEOUT`, overridable via `GSG_TEST_SETSID`/`GSG_TEST_TIMEOUT`; versions `1.2.3`/`4.5.6`).

## git versions and config

- **Config hooks need git >= 2.54.** RHEL host: `/usr/local/bin/git` 2.56; `/usr/bin/git` 2.52 silently ignores `hook.<name>.*`. Tests drive `GIT` (`GSG_TEST_GIT`, default `/usr/local/bin/git`). Config hooks run from the repo root before the hookdir hook, both run, either failing blocks; `--no-verify` skips them; repo-local `hook.git-secret-guard.enabled=false`/`.command` wins.
- **`git hook list pre-commit`** (2.56): `git-secret-guard`, `disabled<TAB>git-secret-guard`, `event-disabled<TAB>...` (`hook.pre-commit.enabled=false`), `hook from hookdir`. Nothing configured = exit **1** + `warning: no hooks found for event 'pre-commit'` (empty, not a failure). Only the command key missing = exit 128. A local `.event=pre-push` ADDS an event, never removes the global one.
- **`git config` exit codes** (2.56): plain set exits 5 on a multi-valued key (use `--replace-all`); `--get-all` exits 1 when absent and also when `GIT_CONFIG_GLOBAL` is a directory; `--global --list` exits 128 for a missing file AND a directory, so "unwritable" is probed by setting/removing a `gsg-install-probe` section (`install_check_config_writable`). `GIT_CONFIG` set makes `git config --global` exit 129. Values are read with `-z --get-all` and stored verbatim (`~` not expanded).
- **`-z` layouts**: `--show-origin --get-all` = `origin NUL value NUL`; `--list`/`--get-regexp` with scope+origin = `scope NUL origin NUL key NL value NUL`, a valueless key is just `key` (`doctor_split_record`); `--file F --get-all` = `value NUL`. Repo-local origins print relative to the cwd (`doctor_origin_text` absolutises). Last record wins. `includeIf "gitdir:"` values show scope `global` with the included file as origin.

## Scanners

**trufflehog 3.99.2**
- Exits 0 on unreadable input even with `--fail-on-scan-errors`, logging only an error-level JSON line: those lines are scan errors and only their `msg` is printed (other fields can hold verifier URLs with the candidate). Findings exit 183. `tests/test_real.sh` pins this and fails if a newer version changes it.
- Exit 0/183 counts only with `{"msg":"finished scanning","chunks":N}`, `N >= 1` (an empty tree gives 0), so `/bin/true` as `TRUFFLEHOG_BIN` is an error.
- A rejected fake credential is `unverified`, hidden by `--results=verified,unknown`; a dead proxy (`HTTPS_PROXY=http://127.0.0.1:9`) makes it `unknown` deterministically. Real-binary tests use that, not the network.

**betterleaks 1.9.0** (`test_real_betterleaks_exit_code_semantics_1_9_0`, `test_real_betterleaks_version_text_and_validation_off_by_default_1_9_0`, `test_real_betterleaks_reads_root_ignore_files_and_configs_on_its_own_1_9_0`, `test_real_betterleaks_inline_markers_and_config_precedence_1_9_0`)
- Clean = 0 and `[]`. `--exit-code N` exists; the default leak status 1 equals the fatal status, so the adapter passes `--exit-code 42` (`GSG_BETTERLEAKS_LEAK_RC`). `WRN skipping ...` (missing target, unreadable file) still exits 0 or the leak code, so skips are errors. `--version` prints `betterleaks version 1.9.0`.
- **Validation is off by default** (counting-proxy probe: 0 connections; with `--validation` 1, and `ValidationStatus` is `error` behind a dead proxy). The adapter never passes `--validation`, so nothing reaches the network and `ValidationStatus` stays null.
- Reads `<target root>/.gitleaksignore` AND `.betterleaksignore` regardless of `--gitleaks-ignore-path` (nested ones are ignored): a commit could mute itself, so the scanned copy renames both to `<name>.gsg-committed` (`betterleaks_stage_tree`). Root `.gitleaks.toml`/`.betterleaks.toml` load only without `--config`; `--config` beats them and the env vars `BETTERLEAKS_CONFIG[_TOML]`/`GITLEAKS_CONFIG[_TOML]`. Inline `gitleaks:allow` and `betterleaks:allow` both work (`--ignore-gitleaks-allow` turns both off). Only `.gitleaks.toml`/`.gitleaksignore` are read from HEAD; the betterleaks-named files are neutralised and never read (`docs/exemptions.md`).
- Runs with cwd = scan dir and path `.`, making `File`/`Fingerprint` repo-relative (`src/a.txt:aws-access-key-id:4`), the form `.gitleaksignore` needs; with an absolute target the fingerprint is absolute and an ignore entry never matches (tests use `env -C DIR ... dir .`).
- Logs: only message words of ERR/FTL/`WRN skipping` lines are printed, cut at the first `key=` word (`msg_words`); over 5000 lines is an error. FTL lines are ANSI-coloured even with `--no-color`: `strip_ansi` before matching `ERR|FTL`. 1.9.0 puts the cause in the message text (`unable to load config, err: ...`), not in a field. Default config skips whole paths through its `prefilter` (`docs/scan.md`).
- **`aws-access-token` is a composite rule**: it needs an `aws-secret-access-key` within 5 lines, so a lone key ID is not reported (gitleaks 8.30.1 did). Our own rule `aws-access-key-id` (`lib/betterleaks-rule.toml`) covers it and is written to equal gitleaks 8.30.1's `aws-access-token` (regex with the `A3T` prefix, `entropy = 3`, `.+EXAMPLE$` allowlist: `test_real_our_aws_rule_matches_what_gitleaks_aws_access_token_did`). The adapter ALWAYS writes `$out/betterleaks.toml` (`[extend] useDefault = true` plus the rule). No HEAD config = ONE run on it. HEAD config = that config exactly as written plus a SECOND run on the generated file with `--enable-rule aws-access-key-id` (1.9.0 logs `Isolating rules`; the default `prefilter` skip list applies to both, so the verdict never depends on an unrelated config: `test_real_a_lone_aws_key_id_under_a_skipped_path_passes_with_and_without_a_repo_config`). No repo config can switch the rule off; an ignore fingerprint or marker still mutes it. gitleaks reported a lone ID as `aws-access-token`, so `betterleaks_write_ignore` adds an `aws-access-key-id` twin for every `<path>:aws-access-token:<line>` line of HEAD's `.gitleaksignore` (plain data transform, bounded by `GSG_BETTERLEAKS_IGNORE_MAX_LINES`). A pair yields both rows on one line and `betterleaks_drop_pair_key_rows` drops the key-ID row. The stand-in tells the runs apart by `--enable-rule` (`STUB_GL_EXTRA_FINDINGS`, `STUB_GL_EXTRA_RC`).
- **Fixtures**: a finding from a built-in rule alone is `generic_key`/`builtin_line` in `tests/test_exemptions_real.sh` (random, `api_key = "<32 chars>"` = `generic-api-key`; trufflehog and our rule are silent). `fake_aws_secret` is random per call (a key pair for `aws-access-token`). Never a credential-looking literal.
- A `--config` without `[extend] useDefault = true` runs only its own rules. **Built-in-rules status is decided by behaviour, never by parsing TOML**: `betterleaks_config_preflight <conf> <work> <timeout>` scans a probe holding `betterleaks_probe_secret` (a bare fake GitHub token: `github-pat` fires alone, a `token = "..."` line would also fire `generic-api-key`, an AWS ID is no use because of the composite rule and our own rule) in the same run as the load check; exit 42 = rc 0 (on), exit 0 = rc 2 (warn `GSG_MSG_BUILTIN_RULES_OFF`), else rc 1 (block). Timeout is explicit; missing/non-positive is refused. A TOML-aware awk and a regex detector were tried and were unsound both ways (multi-line strings, case-insensitive and dotted/inline/quoted keys): **don't reintroduce them** (`test_real_every_spelling_that_keeps_the_default_rules_prints_no_warning`, `test_real_a_use_default_setting_hidden_in_a_multi_line_string_still_warns`, `test_real_an_allowlist_that_covers_everything_also_warns_that_the_built_in_rules_are_off`).
- **`[extend] path` is refused**: it resolves against betterleaks' cwd (the scan tree), so a staged file could become config. The pre-flight runs the HEAD config with cwd = empty `$work/preflight/empty` (before the scan tree exists) on target `$work/preflight/probe`; any non-zero exit blocks (`test_real_every_spelling_of_extend_path_is_refused`). Residual: an absolute path to an existing file still loads (`test_real_an_absolute_extend_path_to_an_existing_file_still_loads_a_documented_residual`).

Inline markers mute one tool each, only on the same line (`docs/exemptions.md`).

## Extraction and the hook

- **Sparse scan files**: added line N sits at line N, the rest blank. Never count scan-tree lines.
- **Diff flags are fixed and explicit** so user diff config cannot change the parse. The awk unquotes C-quoted names and refuses `..`, `.`, empty components and absolute paths (exit 2, block); it dies on a hunk line not `+ - space \` or a diff that ends early. Binary and `-diff` files yield no `+` lines.
- **Config pins**: `staged_diff` runs `git --attr-source=<empty tree>` (else a committed `* -diff` hides text from both tools; `$GIT_DIR/info/attributes` and the system file still apply, documented limit), `-c core.attributesFile=/dev/null`, `-c core.bigFileThreshold=100g` (a small threshold makes files binary). A command-line `-c` beats repo config, `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT`. `tests/test_inherited_config.sh` sets 28 keys in all three forms; add any new one there (`test_other_inherited_git_settings_cannot_change_what_is_extracted`).
- **Environment**: the hook unsets the four `GIT_*_PATHSPECS` right after loading libs (`GIT_LITERAL_PATHSPECS` makes every exclude pathspec match nothing: empty diff, commit unscanned) and exports `GIT_NO_REPLACE_OBJECTS=1` (a `git replace` of HEAD would make another commit's tree the exemption; helper `replace_head_with_permissive_commit`).
- **awk errors**: mawk/gawk exit 2 with their own text (paths may hold control chars). `extract_added_lines` pipes awk stderr through `_extract_clean_stderr` and returns awk's status from `PIPESTATUS`; the hook then says `extracting the added lines of the staged diff failed (...)` (`test_an_extraction_write_failure_blocks_with_a_message_about_extraction_and_keeps_the_awk_line`).
- **Signals**: scanners run as `setsid bash lib/run-scanner.sh` (pid = group id), started and stopped through `lib/proc.sh`. `cleanup`: `kill -TERM -- -pid`, `wait`, bounded poll, KILL, and only then remove the work dir (a surviving `cp -a` could re-create files holding added lines). Adapters use `timeout --foreground`; plain `timeout` makes its own group, which the group kill misses.
- **Pass line** (`report_pass_line`, `report_nothing_line`): the only stderr output on a clean commit. Counts come from `lib/extract.awk` via `GSG_EXTRACT_COUNTS` (`<work>/scan.counts.N`, written in END only on success); `exempt_extract_tree` sums both passes into `GSG_EXTRACT_FILES`/`GSG_EXTRACT_LINES`; `GSG_EXEMPTED` from `exempt_report_exclusions`. A missing/garbage counts file blocks (`test_a_missing_or_garbage_counts_file_blocks_and_never_reports_zero`). Time = `$SECONDS` (`EPOCHREALTIME` needs bash 5, BSD `date` lacks `%N`). Versions from settings `TRUFFLEHOG_VERSION`/`BETTERLEAKS_VERSION` (absent or non-numeric = names only); the hook never runs `--version`. Tests use `assert_pass_line_only`. Finding rows print the scanner in an 11-character column (`betterleaks` is 11).
- **Coverage reminder** (`run_reminder` in the hook, `report_reminder_due`/`report_reminder`/`report_reminder_failed` in `lib/report.sh`; behaviour `docs/scan.md`). Runs AFTER the commit's own output at every decided exit (pass, nothing to scan, findings block, `block()`), only once `REMINDER_READY=1` (work dir exists; earlier blocks, e.g. unusable tools, get none). It starts `"$SETSID_BIN" "$BASH" <share>/bin/git-secret-guard doctor --recheck` as a background job in its own group (`rpid`/`rpgid`, killed by `cleanup` like the scanners), stdout to `$work/recheck.out`, stderr discarded (never copied; a failure prints one `coverage re-check failed (...)` line built from hook-written text). `git rev-parse --local-env-vars` names are unset in the child (`GIT_INDEX_FILE` is set during `commit -a`); `test_the_commits_environment_does_not_reach_the_recheck_of_other_repositories` reads names from a `setsid` stand-in, because a fake `git` on `PATH` never runs inside a hook. The record path comes from `state_dir_path` and `GSG_FINDINGS_MAGIC` (both in `lib/common.sh`, shared with `paths_init`/doctor); `report_reminder_due` skips a missing, empty or header-only record (a clean full run leaves two header lines) and treats anything else as due, so the re-check validates it. No total time limit, by the user's decision. `{ wait "$rpid"; } 2>/dev/null` hides bash's own `Killed` message. Tests: `tests/test_reminder.sh` (installed sandbox machine, `LC_DATA` hook, wrapper scanners that answer `--version`).

## Exemptions

- **Read from HEAD only** (`exempt_head_blob`: `git ls-tree --full-tree HEAD -- <path>`, `git cat-file blob`) for `.secret-scan-ignore`, `.gitleaks.toml`, `.gitleaksignore`. No HEAD or no entry = no exemption. Only modes 100644/100755; a read error, directory, gitlink or **symlink** (it would read as its target text) blocks. git's stderr lands in `EXEMPT_GIT_ERR` -> `cannot read X at HEAD (git said: ...)`. The gitleaks files are materialised as `repo-gitleaks.toml`/`repo-gitleaksignore` (still the user's gitleaks-format files; `.betterleaks.toml`/`.betterleaksignore` are never read). Tests: `tests/test_exemptions.sh`, `tests/test_exemptions_real.sh`.
- **Pathspec semantics** (2.56): patterns become `:(exclude,top,glob)<p>`; `top` is required (without it `/x`, `../x` abort and `.` excludes everything). `*` does not cross `/`; `**`, `**/*`, `**/**` exclude everything; a plain name excludes its subtree; `**/` and `[` exclude nothing; malformed globs never fail. The parser strips leading `/`, `./` and rejects `..`. `scan_ignore_parse` rows: `LINE<TAB>pattern<TAB>as-written`.
- **Excludes cannot be re-included**, so with excludes `exempt_extract_tree` runs two diffs: all but the ignore file with excludes, then the ignore file alone.
- **Catch-all** (`scan_ignore_scope`): a throwaway repo (`git init --template=` in the work dir), built lazily only for patterns with `*?[`, holds probe paths; git's own `diff --cached --name-only` decides. `git rev-parse --local-env-vars` are unset for it (`GIT_INDEX_FILE` is set during `commit -a`). **Union check** `_warn_if_union_covers_tree` compares `git ls-files -z --cached` counts with and without all excludes (per-pattern probes miss `src/** lib/**`). `exempt_warn_rows` is shared with doctor.
- **`--amend` limit**: an amend folding the ignore file and the exempted file into one commit is indistinguishable (`test_amend_can_fold_an_exemption_and_the_exempted_file_into_one_commit_a_documented_limit`).

## Install, uninstall, state (behaviour: `docs/install.md`)

- **Release tarballs**: `trufflehog_<v>_linux_{amd64,arm64}`, `betterleaks_<v>_linux_{x64,arm64}` (vendors name x86_64 differently; betterleaks 1.9.0 ships `.tar.gz` for linux and darwin, checksums in its `checksums.txt`). `tools_version_matches` accepts the pin only as a whole word or `v<pin>`.
- **Download override is test-only and cannot skip verification**: `GSG_TOOLS_BASE_URL` + `GSG_TOOLS_LOCK`, announced as `TEST OVERRIDE active` (`test_the_base_url_override_cannot_skip_verification`). curl: `-q` first (ignore `~/.curlrc`), `--proto =https --proto-redir =https`.
- **Everything refusable runs before anything changes**: `install_check_prerequisites` (all missing prerequisites named with hints and a count; curl only if a download is needed, systemctl only with `--with-timer`), platform, `core.hooksPath` read/refusal, CLI link, config write probe, state, `install_plan_lock`, download + SHA-256 + `--version` of all tools into one `mktemp -d` stage, `install_hash_staged`, backup, **state write**, place tools, share tree (built beside, renamed in), CLI link, `git config --replace-all` event + command, unset `core.hooksPath` LAST (`test_install_keeps_scanning_when_the_final_hooks_path_unset_fails`). State precedes config so an interrupted install can be uninstalled.
- **Uninstall restores `core.hooksPath` FIRST**, then removes the hook section, timer, CLI link, share dir; a failed restore keeps everything for a rerun (`test_uninstall_restores_core_hooks_path_before_removing_the_hook_config`). Never leave a machine with neither hook nor hooksPath.
- **State** (`${XDG_STATE_HOME:-~/.local/state}/git-secret-guard/state`): `version`, `previous_hooks_path_set`, `previous_hooks_path`, `tools_installed_by_us`, `backup_path`, `tools_replaced`, `tools_placed`, `timer_installed`. `state_write` writes all eight; `state_read` still accepts older five/six-key files and refuses anything odd.
- **Recorded hooksPath** is never overwritten; `no` is replaced by a later takeover (`test_a_hooks_path_taken_over_after_a_plain_install_is_recorded`). A recorded value differing from the current one refuses (`install_check_recorded_hooks_path`); the way out is `uninstall` then `install --replace-hooks-path`.
- **Backup bounds** (`install_check_backup_bounds`): refuses `/`, `$HOME`, over `GSG_BACKUP_MAX_BYTES`/`GSG_BACKUP_MAX_FILES`. Test `/` only at resolver level (`test_the_resolver_refuses_root_before_anything_could_back_it_up`), never by running install.
- **Scanner files: ours are replaced in place, anyone else's are moved aside.** `install_owns_file` = hash recorded in `tools_placed` (any recorded hash); otherwise (or a symlink) plan `<tool>.gsg-replaced-<UTC>`. `install_write_state pending` records old AND new hash before `install_commit_tools`, `final` keeps the new one, so a failed placement stays recognisable. `mv -T -n` is followed by checking both paths (coreutils 8.32 exits 0 when `-n` skips). `uninstall_restore_replaced`: first valid record per tool decides; restore only over an empty path or a recorded hash, never a symlink; validated with `GSG_ASIDE_RE` + `GSG_TOOL_NAMES`. `uninstall_tools` deletes only regular files whose hash is in `UN_PLACED`. Pin bumps: `tests/test_upgrade.sh` (`bump_pins`).
- **Legacy gitleaks** (state written by the gitleaks build): `GSG_STATE_TOOL_NAMES` (current + `GSG_LEGACY_TOOL_NAMES`) is what uninstall and doctor validate state words against, so an old state is still understood. Install: `install_note_legacy` keeps the legacy `tools_placed` words in `GSG_LEGACY_PLACED`, `install_write_state` carries them through the pending/final writes, and `install_retire_legacy_tools` runs LAST (after `install_unset_hooks_path`, the new hook is live) to remove a legacy file whose hash is recorded (`install_owns_file`), restore the first moved-aside original onto the empty path (`mv -n`, both paths checked), and leave a foreign file in place (aside record kept). A failed step returns before the clear, so the next install retries. Right after our file is removed the state is rewritten WITHOUT our placed hash and before the user's file is moved back, so an interruption after the restore cannot make the rerun match the (possibly byte-identical) restored file and delete it (`test_an_interruption_after_the_restore_never_lets_the_rerun_delete_the_users_gitleaks`). `tests/test_legacy_gitleaks.sh`.
- **hooksPath reader** (`lifecycle_read_hooks_path`, sets only `GSG_HP_*`; `GSG_PREV`/`GSG_PREV_SET` are install's). `git config --global` reads one file, yet XDG and included files still apply globally, so it also runs `git -C / config --show-scope --show-origin -z --list` and treats other-file values as foreign. `includeIf` is invisible outside a repo, so `hp_walk_includes` reads every include target (bounded by `GSG_HP_MAX_INCLUDES`); missing targets are skipped like git (`hp_include_target`), unresolvable ones refused (`hp_report_unresolved`). `lifecycle_realpath_m` works without GNU `realpath -m`. `lifecycle_note_global_config` prints a note when `GIT_CONFIG_GLOBAL` is set (every lifecycle test's stderr has it).
- **Testing the global-config write probe**: to hit "cannot write" make the config DIRECTORY unwritable (git writes through a lock file; a read-only file is not enough); a directory used as the global config fails earlier, at the read ("cannot read").
- **`/etc/os-release` is data, never sourced** (`install_os_release_field`; `GSG_OS_RELEASE` for tests; `test_the_container_script_reads_os_release_as_data`). Hints: `install_os_family`, `install_fix_hint`, `install_git_hint` (`tests/test_prerequisites.sh`).

## Doctor and timer (behaviour: `docs/doctor.md`)

- **Severity**: exit 1 only for a PROBLEM; WARNING/info never change it (`/usr/bin/git` 2.52 is permanently reachable on the RHEL host, so failing on warnings would make "healthy" impossible).
- **Runs nothing a repository configures**: `doctor_start` exports `GIT_NO_REPLACE_OBJECTS=1`, `GIT_OPTIONAL_LOCKS=0`, `GIT_NO_LAZY_FETCH=1`, unsets the four `GIT_*_PATHSPECS` and all `git rev-parse --local-env-vars` (incl. `GIT_DIR`, `GIT_CONFIG_COUNT`), and only AFTER that sets `GIT_CONFIG_COUNT/KEY_0/VALUE_0` = `core.fsmonitor=false` (`git ls-files` runs fsmonitor; `cat-file` in a `blob:none` clone starts `uploadpack`). Tests: `test_doctor_runs_no_command_a_repository_configures`, `test_doctor_never_lazy_fetches_from_a_promisor_remote`, `test_an_inherited_git_dir_cannot_point_every_check_at_one_repository`. Doctor-only on purpose: the hook runs in the committer's own repo.
- **Discovery**: `find ROOT -maxdepth 4 -name node_modules -type d -prune -o -name .git -prune -print0` under `LC_ALL=C`, bound `GSG_DOCTOR_MAX_ENTRIES`. Group by `--git-common-dir` (two separate `rev-parse` calls; names may hold newlines). `doctor_resolves_here`: an empty `.git` makes git answer for the parent. A find failing only with `Permission denied` -> `doctor_unreadable` lists PROBLEMs and continues; other failures exit 2.
- **Worktrees**: `doctor_check_worktrees` runs `doctor_repo_hook` per checkout (`extensions.worktreeConfig` can disable the hook in one); duplicates dropped via `DR_SEEN`/`DR_TREE_LABEL`.
- **Time bounds**: `doctor_bound_git` writes a `git` shim (first on `PATH`, also `GSG_GIT`) running git under `"$TIMEOUT_BIN" -k 5 $DR_LIMIT` **without `--foreground`** so the whole group dies (`test_a_timed_out_doctor_run_leaves_no_process_behind`); Ctrl-C therefore waits for the current call. Limit `DOCTOR_TIMEOUT_SECONDS` (settings only, default 30); the betterleaks pre-flight takes the smaller of it and `SCAN_TIMEOUT_SECONDS`.
- **Never print a configured value** (`doctor_values_text`; `test_the_machine_section_never_prints_a_hook_config_value`). Cut text only through `trunc_text` (sanitise first) and read git stderr files through `first_message`.
- **Reuse, don't copy**: `exempt_warn_rows`, `GSG_MSG_BUILTIN_RULES_OFF`, `tools_probe_version`, `settings_tool_bin`, `install_collect_gits` (it looks up `PATH`, hence lives in `lib/install.sh`).
- **Findings record** (`lib/doctor_findings.sh`, `<state dir>/findings`, behaviour: `docs/doctor.md`): doctor's ONE write, so the readonly test prunes only it and its lock. Only PROBLEMs; data, never sourced, validated per line (`doctor_rec_line_ok`); invalid = exit 2 and no action, a full run repairs it. Written only after a finished run (exit 2 leaves it), by temp + `mv` in the same dir, merged under the lock from a fresh read (a stale in-memory copy would lose a concurrent run's records). A full run replaces machine records and records of repos it saw; a record under its roots goes only when the repo is PROVEN gone (`doctor_rec_proven_gone`), never because discovery missed it (depth, node_modules, unreadable dir). `--recheck` replaces machine records and the recorded repos and keeps the `time` of the last full run. An invalid record contributes nothing (`DR_REC_OLD` is assigned only after the whole file validated); limits are 100000 lines and 64 MiB (`GSG_FINDINGS_MAX_*`, one definition for reader and writer; size is checked before the file is read). **Doctor never writes what it cannot read**: `doctor_rec_check_size` refuses an over-limit temp file before the `mv`, keeps the old record and the run exits 2. Per-line checks must stay linear (`${line//[^$'\t']/}` is quadratic: minutes on a 1 MiB line). `findings.XXXXXX` temps older than a minute are cleaned under the lock. `uninstall_run` takes the lock right after `state_read`, BEFORE anything is removed (a refused lock changes nothing, so the installed CLI its message names still exists; exit 1), holds it through `uninstall_steps`, releases it on every return path and only then `rmdir`s the state dir (the lock link lives there). The refused-lock test reruns with the INSTALLED CLI: a checkout-run test hid a half-done uninstall once. An invalid record says `replacing it` in a full run and `run ... doctor to replace it` in a recheck (`DR_RECHECK`). The lock-scope guard is a source test because the probes are bash builtins (`[ -d ]`), which no PATH stand-in can see. A path the record cannot hold is skipped whole-repo with a stderr note (never partial).
- **`--recheck`** reuses `doctor_start`, `doctor_machine_checks`, `doctor_classify_dir`/`doctor_finish_discovery` and `doctor_repo_loop` (so every protection holds) but never runs `find`. It validates the record BEFORE `doctor_require_git` so an empty record runs no git (`test_recheck_with_no_record_or_an_empty_one_prints_nothing_and_runs_no_git`). stdout = open PROBLEMs only (story #15 shows it as is); notes about dropped repos go to stderr. `DR_FIND_TREE` runs parallel to `DR_FIND` so a worktree finding is recorded with its worktree. Unreadable directories are not recorded: only discovery sees them.
- **Lock** = symlink `findings.lock` -> holder pid (`ln -s` is atomic and names the owner; macOS has no `flock`, mkdir + pid file is two steps). Held only for read-merge-rename, never during checks (so recheck needs no time limit). Stale = `kill -0` fails; a dead holder is broken and retried at once, no sleep after the last look. Tests shorten the wait with a stand-in `sleep` on the sandbox PATH, not a production flag.
- **Timer**: units carry `GSG_TIMER_MARKER` on line 1; only marked files are touched. `SYSTEMCTL_BIN` is in settings only when a timer is wanted or recorded. A plain install over `timer_installed=yes` never enables it and never needs systemctl (`install_refresh_timer_units`); only `--with-timer` sets `INSTALL_TIMER_ENABLE`. Units get `PATH` (`timer_unit_path`) and the set `GSG_TIMER_ENV_NAMES` as `Environment=` (the user manager does not pass the login env); unescapable values are refused (`timer_check_values`).
- **launchd agent** (macOS, `lib/launchd.sh`; behaviour: `docs/doctor.md`): `INSTALL_TIMER_BIN` is systemctl or launchctl by OS, settings key `SYSTEMCTL_BIN` or `LAUNCHCTL_BIN`; the one `type -P launchctl` is in `install_find_timer_bin`. The marker is an XML comment, so no `--` (it is not `GSG_TIMER_MARKER`). **Plist layout: line 1 = XML declaration, line 2 = DOCTYPE, line 3 = marker comment** (`launchd_plist_is_ours` checks lines 1 and 3). launchd parses plists with libxpc, not CoreFoundation, so `plutil -lint` passing proves nothing about launchd, and Python `plistlib` rejects a comment before the DOCTYPE; the standard header order is the safe layout. `GSG_LAUNCHD_LABEL` lives in `state.sh` because `paths_init` builds `GSG_AGENT_PLIST` from it under `set -u`. `launchd_string` quotes its `${v//&/"&amp;"}` replacements: bash 5.2 `patsub_replacement` turns a bare `&` into the match. XML escaping covers `& < > "`; control characters cannot be escaped and refuse the install. A bootstrap of a loaded label fails, so install `print`s first and boots out a loaded agent; uninstall `print`s too, because a bootout of an agent the user unloaded fails and would block uninstall forever. The log is `doctor.log` in the state dir (launchd makes no directories, `launchd_write_plist` creates it); uninstall removes it, else the state dir stays. The stand-in `lc_launchctl_standin` is stateful (`launchctl.loaded`) and fails an unmodeled subcommand loudly.
- **`systemd-analyze --user verify`** needs `XDG_RUNTIME_DIR`: tests give it a sandbox dir (`verify_units` in `tests/test_timer.sh`), never the real one. Without a system bus it complains, so the Ubuntu container starts `dbus-daemon --system --fork`.

## Platforms (`docs/platforms.md`)

**Linux**
- RHEL host = Rocky Linux 9.7. Ubuntu's PPA git lives in `/usr/bin/git` (hence `GSG_TEST_GIT`, `lc_first_git_dir`).
- All awk programs give identical bytes under gawk, mawk 1.3.4 and macOS bwk: no gawk dependency. `tests/test_awk_portability.sh` picks the interpreter via `awk_farm` and skips with a reason when one is absent.
- **`set -o pipefail` + `sed ...q` inside `$( )` is a race** (writer gets SIGPIPE); it once turned a good PPA install into a silent source build.
- **A failed redirection is reported before `2>/dev/null` applies**: write `{ mapfile ... <"$f"; } 2>/dev/null`.

**Containers** (`tests/platform/`). **Read `docs/platforms.md`, including its "Maintainer notes", before changing anything here.**
- `ubuntu.sh` (host, the RHEL trust-boundary launcher) -> `ubuntu-container.sh` (root; sourceable, `main` runs only when executed) -> `ubuntu-e2e.sh` (`gsguser`), tested via `--dry-run` and sourced functions by `tests/test_platform.sh` (skipped on Darwin). `mac-linux.sh` is a regression run, not a boundary; `rocky-container.sh` sources `ubuntu-container.sh` and redefines `usage`, `install_git_source`, `phase_prepare`. `ubuntu.sh` must never mention `--skip-isolation` (`tests/test_mac_runner.sh`).
- The container copy is `git ls-files -co --exclude-standard`, so `.gitignore` must keep scratch, `.env*` and local tool state (`.code-indexer/`, `.code-indexer-override.yaml`, `.ssh-mcp-server.port`) out while `reports/bugs/`, `reports/reviews/` stay committable (`test_the_project_gitignore_keeps_scratch_and_secret_paths_out_of_the_container_copy`).
- **A failed `ppa_disable` stops the git step**: `install_git_ppa` returns 2 and no source build runs, because its root `apt-get install` would trust a PPA that may still be enabled.
- Rocky also installs the stock distro git: `test_doctor` calls `/usr/bin/git` directly.
- Mac runner gotchas: `stage_checkout` runs `git init` in the copy (`tests/test_quality.sh` uses `git ls-files`); BSD `mktemp -t` appends a suffix; macOS bash rejects regex repetition > 255.
- Helpers: `isolation_with` (Ubuntu `OS_RELEASE` fixture so `check_isolation` passes anywhere), `dev_baseline`, `ns_fixture`, `baseline_with`, `mountinfo_fixture MP[=FSTYPE]`, `PPA_STUB_ENV` (`STUB_LOCK` needs non-root).

**macOS** (arm64, macOS 26.7.1; Homebrew required)
- Apple Git 2.54.0 honours `hook.<name>.command`/`.event` but has **no `hook.<event>.enabled`** (that doctor test skips). `/bin/bash` 3.2.57 cannot even parse the libs (`mapfile`, `declare -g`, `local -A`). No `setsid`, `timeout`, systemd, `/proc`. `util-linux` is keg-only (`opt/util-linux/bin/setsid`); GNU names are in `opt/coreutils/libexec/gnubin`.
- **Bootstrap**: `brew_cli_bootstrap` re-execs under a Homebrew bash >= 4.4; for `install` with none it runs `brew install bash` ALONE first; else refuses (`brew_refuse_old_bash`, never install wording for other commands). An installed copy without brew reads `BASH_BIN` from settings as data (`brew_recorded_bash`; only absolute `[A-Za-z0-9._/+@%-]` paths), checks it with `brew_bash_ok` and execs. Two loop bounds: pid-bound `GSG_BREW_BOOTSTRAPPED` (`test_a_recorded_bash_that_is_really_bash_3_2_is_refused_after_one_exec_not_looped`) and `GSG_BREW_REEXEC_DEPTH` at `BREW_REEXEC_MAX` (`test_a_recorded_bash_wrapper_that_runs_bash_as_a_child_is_refused_by_the_depth_bound_not_looped`). These need a real bash 3.2 and skip on Linux.
- **Install order** (user decision): `brew_inspect` (`brew_find` = `type -P brew` only, never guess `/opt/homebrew`) and `install_macos_inspect` only detect. The rest is ONE `brew install` in `install_macos_finish` (via `install_tools_ready`) after every refusable check and `install_plan_lock`. With a GNU `timeout` already present, download/verify/`--version` run before brew; without, after it (`install_stage_refused`). **Every install refusal uses `brew_unchanged_text`** (`nothing was changed` until brew ran, then names what brew installed), enforced by `test_every_install_refusal_wording_is_honest_after_a_brew_install` (two allow-listed exceptions). `curl_order_recorder` proves download order. Scanners never come from brew.
- **Runtime**: settings add `BASH_BIN`, `GNUBIN_DIR`. Hook command = `hook_command_text` (`'<bash>' '<share>/hooks/secret-scan'`, shared via `share_recorded_bash`, `DR_HOOK_CMD`). The hook has a bash 3.2 syntax guard at the top and prepends `GNUBIN_DIR` (relative/missing = block); `brew_use_gnubin` does the same for the CLI and refuses all but `install`/`version`/`help` without a GNU dir (`test_a_command_that_needs_the_gnu_tools_refuses_when_their_directory_is_missing`).
- **BSD differences that shaped code**: no `realpath -m`, `mktemp --suffix`, `mv -T`, `stat -c`, `env --default-signal`; `install -T` means tags; `chmod 700 -- DIR` fails; `find` lacks `-printf`/`-readable`/`-executable` (sizes via `install_entry_sizes`; never `find -ls`, whose size column shifts with spaced owner names: `test_the_backup_bounds_do_not_depend_on_the_owner_columns_of_find_ls`); `wc -l` pads. bash 5.3 in the C locale reads a UTF-8 `…` after `$name` as part of the name: write `${name}…`.

## Testing tricks

- **Lifecycle helpers** (`tests/lifecycle.sh`): `lc_begin` (wipe sandbox; `lc_systemctl_standin` logs to `$SANDBOX/systemctl.log`, fails on text in `$SANDBOX/systemctl.fail`; `lc_brew_standin` with `brew.map`, `brew.fail`, `brew.failon`, `brew.nopopulate`), `gsg` (CLI under `env -i`), `lc_make_fixtures`/`lc_use_fixtures`, `lc_path_without TOOL`, `lc_git_wrapper '<sh condition>'` (fails only matching calls), `lc_real_lookup` + `gitreal` (git's real include lookup on the scratch HOME). Doctor helpers (`tests/doctor.sh`): `dr_begin`, `dr_repo NAME`, `doctor`.
- **The hook never sees a fake `git` on `PATH`** (git prepends its exec-path). Inject `setsid`/`timeout` via settings (`use_stubs "SETSID_BIN=..."`). To break only the hook's probe repo, point `GIT_CONFIG_GLOBAL` (`set_env`) at a copy plus `[includeIf "gitdir:<TMPDIR>/"]`. To break doctor's git, use a wrapper failing `git -C /` with 128. `GIT_TEST_ASSUME_DIFFERENT_OWNER=1` simulates `safe.directory`.
- **Stand-ins** report configured findings whatever the tree holds: clear `STUB_GL_FINDINGS` between steps and assert on `STUB_RECORD` (per-tool suffix). betterleaks without `--report-path` = pre-flight (`STUB_GL_PREFLIGHT_RC/ERROR/SLEEP`); a call with `--enable-rule` = the rule-only run (`STUB_GL_EXTRA_FINDINGS/RC`); only real-betterleaks tests settle config meaning. A stand-in that must be killed needs `exec sleep`; timing assertions allow one extra sleep for the `--version` probe.
- **Signals**: background jobs start with SIGINT ignored, so INT tests launch git with `env --default-signal=INT`. Never `pkill -f` a pattern that is in your own command line.
- **Old git**: compute expectations from `/usr/bin/git --version`; a fake old git goes AFTER the real one on PATH.
- **Stdin socket quirk**: with a socket on stdin, `env -i ... bash -c` reads `~/.bashrc` and changes `type -P` answers; tool-lookup helpers (`dr_which`, `lc_which`, `lc_first_git_dir`) redirect stdin from `/dev/null`.
- **On a Mac**: always `tests/run.sh FILE` (it puts the brew bash and gnubin first; plain `bash tests/test_x.sh` gets BSD tools). `tests/lib.sh` picks per-OS `TEST_BASE_PATH`, `TEST_BASH`, `TEST_GNUBIN`, `TEST_TRUE` and pinned scanners from `~/.cache/git-secret-guard-test-tools` (`tests/fetch-test-tools.sh`). `lc_begin` fakes a Linux `uname`; `tests/test_macos.sh` uses `lc_real_uname`/`as_macos`. A test replacing `PATH` must keep `$SANDBOX/pathbin`, or the real brew is reachable. `FILE_SKIP_REASON` skips a whole file with a reason.

## Conventions

- Comments follow `~/.claude/coded-comments` (`# ^ tag clause`), sparse. Lint: `tests/comment-rules.awk FILE` (`test_every_comment_follows_the_coded_comments_rules`). Tags: hazard coupled security invariant external order why see perf todo; `why X, not Y; reason`; <= 160 chars, <= 3 coded lines in a row; no ` so `, ` but `, ` because `, ` which `, ` that `, ` then `, ` while `, `: `.
- `set -u`; check every return value; bounded loops; shellcheck clean (info included) at `GSG_SHELLCHECK_PIN` 0.11.0 (other versions skip the gate). A local named like a sourced array (`lines`) trips SC2178/SC2128.
- Names must not be confusable (`INSTALL_TIMEOUT_BIN` is a path, not a duration).

## Correct as written: do not "fix"

Reviewers flagged each of these; each was probed and is right.
- `wait "$!"` after `done < <(find ...)` or `mapfile < <(git ...)` returns the substituted command's status (bash 4.4+). A process substitution for a stderr filter would race the function's return, hence pipe + `PIPESTATUS`.
- `${v%"${v##*[!/]}"}` trims all trailing slashes; `type -aP git` is valid bash.
- A line of only assignments (`A=0 B=""`) sets both in the current shell; `${kv#*$'\n'}` needs its guard for valueless records.
- `doctor_unreadable` returning 1 means "not explained by permissions" (caller exits 2); `$key` in `doctor_repo_info` is the absolute common dir.
- A token in a remote URL path (not `user:pass@`, which git strips) can appear in `EXEMPT_GIT_ERR` on the user's own stderr: accepted, it is the user's config shown to the user.
- `/proc/self/mountinfo` field 5 is the mount point, fstype follows the lone `-`. `awk -F: '$1 == "fpr" {print $10}'` is right for `gpg --with-colons`.
- `lib/extract.awk` writes nothing to stdout, so `2>&1 |` into the sanitizer swallows no extracted lines.
- Doctor's git shim omits `--foreground` on purpose; the hook adapters keep it on purpose.

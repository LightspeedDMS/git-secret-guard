# git-secret-guard: project notes

Bash tooling (no Python/Node): a git config hook (`hook.git-secret-guard.*`) runs trufflehog and betterleaks on the lines each commit adds. Issues live in GitHub LightspeedDMS/git-secret-guard (epics #1, #8). Behaviour is in `README.md` and `docs/{install,platforms,scan,exemptions,doctor}.md`; read the matching doc before changing behaviour. Each doc ends with **Maintainer notes** (internals, function and test names). This file holds only the rules and the invariants a "simplification" breaks.

## Layout

- `hooks/secret-scan`: the hook git runs; `<share>` = two levels above its resolved path, settings in `<share>/settings`. Hook libs: `lib/common.sh`, `lib/extract.{sh,awk}`, `lib/exempt.sh` (doctor reuses it), `lib/report.sh`, `lib/scanners/{trufflehog,betterleaks}.sh`, `lib/betterleaks-rule.toml`, `lib/run-scanner.sh`, `lib/proc.sh`.
- `bin/git-secret-guard`: the CLI (`install [--replace-hooks-path] [--with-timer] [--upgrade-git] [--take-over-system-git]`, `uninstall [--remove-tools] [--keep-system-git]`, `restore-system-git`, `status`, `doctor [--roots DIR...]`, `version`, `help`; help in `lib/usage.md`; ends with `main "$@"; exit` so bash never reads a file `install` just replaced). CLI-only libs: `lib/{state,tools,hookspath,install,install_cmd,install_tools,uninstall,status,timer,launchd,doctor,doctor_repos,doctor_findings,brew,wsl,gitup,gitup_source,gitup_rpm,gitup_apt,gitup_wsl,gitup_takeover,gitup_windows}.sh`; the hook never loads them (`test_the_hook_never_loads_the_install_time_libraries`, `test_the_hook_never_loads_the_doctor_and_timer_libraries`).
- Tests: `tests/run.sh [FILE]`, harness `tests/lib.sh`, stand-ins `tests/stubs/`, helpers `tests/lifecycle.sh` (`lc_begin`, `gsg`), `tests/doctor.sh` (`dr_begin`, `dr_repo`, `deep_path`) and `tests/gitup.sh` (`gu_*`, used by `tests/test_gitup*.sh`), `tests/coverage.sh`; container runs in `tests/platform/` (not in `run.sh`; `rpm.sh rocky|fedora` runs the git upgrade E2E). CI: `.github/workflows/tests.yml` (Ubuntu head vs base compare; on Windows the whole suite plus a clean-machine install/leak/uninstall job; `macos-suite` on `macos-26` arm64 runs the whole suite, then `.github/scripts/check-macos-tests.sh` fails the job unless every test in `tests/macos-only.list` is a PASS line, so add a test that skips off a Mac to that list; job `macos-list-complete` runs `check-macos-unlisted.sh` on the Mac log and the Linux `log-head` and names one left out).
- Windows (Git for Windows) is first class: front ends `bin/gsg-bash.cmd`, `bin/git-secret-guard.cmd`, `tests/run.cmd`; `tests/test_windows.sh` fakes `uname` around the real libs, so the Windows branches also run on Linux and macOS; `tests/windows-skips.list` names what cannot apply. The Windows suites themselves do not run on a Mac (only CI runs them).

## Hard rules

- **Test isolation.** Each test file runs in `~/.tmp/git-secret-guard-tests.XXXXXX`: scratch `HOME`, `GIT_CONFIG_GLOBAL=<scratch>`, `GIT_CONFIG_NOSYSTEM=1`, `env -i`. The real `~/.gitconfig` sets `core.hooksPath=~/.config/git/hooks`: it must never apply, and nothing under `~/.config/git/` is ever modified. `PYTHONUSERBASE` points at the real `~/.local` (pre-commit is a `pip --user` install).
- **Fake secrets** are built at runtime (`fake_aws_key`, `fake_github_token`, `fake_aws_secret`), never printed; leak tests assert a marker is absent with `no_leak`. `tests/test_quality.sh` scans the tree with the real tools (`..._KEY=<40 hex>` trips betterleaks' `generic-api-key`).
- **Never dump the environment** in a probe hook (`env` once printed real API keys); log only `GIT_*` under `env -i`.
- **No real `brew` or `systemctl` in lifecycle tests**: `lc_begin` puts recording stand-ins first on every lifecycle `PATH`. The only real `systemctl` call is the read-only `systemctl show $GSG_TEST_SERVICE_UNIT` in `service_prepare` (`tests/lib.sh`, service-environment emulation, skips when the variable is unset). Contribution rules: `CONTRIBUTING.md` (DCO sign-off, checked by `.github/scripts/check-dco.sh`).
- **Tool paths come only from the settings file.** `load_settings` unsets every settings key (and the old `GITLEAKS_*`) before sourcing; the hook checks the five tool paths with `tool_unusable` (else block, "nothing was scanned"); on Windows the settings hold `TASKKILL_BIN` instead of `SETSID_BIN`, and `JQ_BIN` is a wrapper in the share dir. Only `lib/install.sh` and `lib/brew.sh` may `type -P` (`test_the_hook_never_looks_tools_up_on_PATH`, `test_systemctl_is_looked_up_only_in_lib_install_sh`, `test_launchctl_is_looked_up_only_in_lib_install_sh`). bash (Linux shebang), git, awk, sed, coreutils do resolve via `PATH`; child scripts run under `"$BASH"` (docs/scan.md#how-it-works).
- **Settings** are generated by `install_write_settings` (`printf %q`; the hook sources them) on every install; `write_settings` in `tests/lib.sh` writes the same keys for hook suites.

## git

- **Config hooks need git >= 2.54.** RHEL host: `/usr/local/bin/git` 2.56; `/usr/bin/git` 2.52 silently ignores `hook.<name>.*`. Tests drive `GIT` (`GSG_TEST_GIT`; default `/usr/local/bin/git`, `/usr/bin/git` on macOS, the one on `PATH` on Windows). Config hooks run before the hookdir hook, both run, either failing blocks, whatever `core.hooksPath` says.
- git 2.56 output formats and exit codes the code relies on: docs/doctor.md#maintainer-notes (`git hook list`, `-z` layouts), docs/install.md#maintainer-notes (`git config` exit codes).

## Invariants: what breaks if you "simplify"

- **Scanner semantics are pinned per version** (trufflehog 3.99.2 exit 0 on unreadable input, `chunks >= 1`; betterleaks `--exit-code 42`, `WRN skipping` = error, validation never passed): docs/scan.md#maintainer-notes, `tests/test_real.sh`. Offline tests use a dead proxy (`HTTPS_PROXY=http://127.0.0.1:9`) so a fake credential is `unknown`; one online test skips offline.
- **A commit cannot mute itself**: explicit `--config`/`--gitleaks-ignore-path` always; root `.gitleaksignore`/`.betterleaksignore` renamed `<name>.gsg-committed` (`betterleaks_stage_tree`); exemptions read from HEAD only (`exempt_head_blob`, modes 100644/100755, a symlink blocks).
- **Lone AWS key ID**: our rule `aws-access-key-id` always runs, a second `--enable-rule` run when HEAD has a config (`test_real_a_lone_aws_key_id_under_a_skipped_path_passes_with_and_without_a_repo_config`, docs/scan.md#limits).
- **Built-in-rules status by behaviour, never by parsing TOML** (`betterleaks_config_preflight`: betterleaks exit 42 / 0 / other = on / warn / block, returns 0 / 2 / 1); a relative `[extend] path` fails by running from an empty cwd (`test_real_every_spelling_of_extend_path_is_refused`; an absolute path to an existing file still loads, a documented residual). Don't reintroduce awk/regex TOML detectors (docs/exemptions.md#maintainer-notes).
- **Extraction**: sparse scan files, never count scan-tree lines (`test_a_missing_or_garbage_counts_file_blocks_and_never_reports_zero`); fixed diff flags plus `--attr-source=<empty tree>`, `core.attributesFile=/dev/null`, `core.bigFileThreshold=100g` (`4095m` on Windows; add new keys to `tests/test_inherited_config.sh`); the hook unsets the four `GIT_*_PATHSPECS` and exports `GIT_NO_REPLACE_OBJECTS=1`.
- **Pathspecs** `:(exclude,top,glob)<p>`: `top` is required; excludes cannot be re-included, so `exempt_extract_tree` runs two diffs; catch-alls are judged by git itself (`scan_ignore_scope`, `_warn_if_union_covers_tree`).
- **Signals**: scanners and the reminder run in their own group (`lib/proc.sh`: `setsid` on Linux/macOS; on Windows no groups, a `/proc` walk for current Windows pids, then `taskkill /T /F`); `cleanup` kills, waits, then removes the work dir. Adapters keep `timeout --foreground`; doctor's git shim omits it (`test_a_timed_out_doctor_run_leaves_no_process_behind`). `hooklist_read` runs git as a foreground command writing a file, never `< <(...)`: bash 5.3 (macOS) starts process substitution children with SIGINT ignored and git outlived Ctrl-C (#68, `test_the_hook_list_call_runs_in_the_foreground_not_in_a_process_substitution`).
- **Output**: a clean commit prints exemption notices, one pass line (`report_pass_line`, counts from `GSG_EXTRACT_COUNTS`) and the coverage reminder (`run_reminder`, only after `REMINDER_READY=1`; plain `"$BASH"` instead of `"$SETSID_BIN"` on Windows); the commit's own exit status never depends on the reminder.
- **Install order**: refusable checks before any lasting change (exceptions: the macOS `brew install bash` bootstrap, the set-and-remove config write probe, staging after brew when no GNU `timeout` exists, and a refusal after an accepted git upgrade, which says what changed through `GITUP_CHANGED`/`brew_unchanged_text`); state before config; unset `core.hooksPath` last (`test_install_keeps_scanning_when_the_final_hooks_path_unset_fails`). Uninstall restores it first (`test_uninstall_restores_core_hooks_path_before_removing_the_hook_config`).
- **Scanner files**: ours (hash in `tools_placed`, `install_owns_file`) are replaced in place, anyone else's moved aside; every path is built with `tools_binary_name` (`.exe` on Windows); legacy gitleaks retired last, state rewritten before the restore (`test_an_interruption_after_the_restore_never_lets_the_rerun_delete_the_users_gitleaks`). Download override cannot skip verification (`test_the_base_url_override_cannot_skip_verification`). `/etc/os-release` is data, never sourced.
- **Doctor**: exit 1 only for a PROBLEM (WARNING/info never; `/usr/bin/git` 2.52 is permanently reachable on the RHEL host). Runs nothing a repository configures (`doctor_start`, `GIT_NO_LAZY_FETCH=1`, `core.fsmonitor=false` set after the `GIT_*` cleanup). Never prints a configured hook `command`/`event` value (`doctor_values_text`, `test_the_machine_section_never_prints_a_hook_config_value`); a disabling `enabled` value is shown; other values are cut with `trunc_text`. Discovery is one mechanism: `doctor_prune_args` (`-samefile`, default macOS run only, `Library` and `.Trash`) on both finds.
- **Status**: exit 1 when not installed or a line says `MISMATCH`/`MISSING` (global config, hook command, settings, tools, takeover, the first git on `PATH` older than 2.54 or unreadable, a hook git does not run); call sites and tests: docs/install.md#maintainer-notes. Share files: `status_hook_files` walks `GSG_HOOK_LIBS` and `GSG_HOOK_FILES` (`lib/common.sh`), the lists the hook itself loads from, so a new hook library goes there and nowhere else (`test_the_hook_loads_exactly_the_libraries_in_the_shared_list`). Settings keys (`status_settings_keys`, macOS tests use the fake `uname`): `GNUBIN_DIR` by `gnubin_dir_unusable` (shared with the hook, checked on every platform when set), and on macOS only `BASH_BIN` by `tool_unusable` + `brew_bash_ok` and `LAUNCHCTL_BIN` when `ST_TIMER=yes`; a `BASH_BIN` line on Linux still gives `global config: MISMATCH` (older than #67, left as is); a `BASH_BIN` that is no bash and exits 0 lets a commit land unscanned (docs/platforms.md#macos-homebrew). `status_git` runs first and skips the hook check when it fails. **One verdict, git's**: `hooklist_probe_line` (`lib/hookspath.sh`, shared with doctor's machine section via `doctor_hook_verdict`) runs `git hook list pre-commit` in a throwaway bare repo written by hand (`HEAD`, `objects/`, `refs/`; never `git init`, which fires the user's `reference-transaction` hooks), under the settings' `timeout` (30 s) when usable; `hooklist_read` is also what `doctor_repo_hook` uses. `hp_hook_enabled_scan` only locates the setting git blamed (key, scope, file, advice) and never decides; no enabled word list, no version gate for the event key (git reports `event-disabled` only where it reads it); a value-less key makes `hook list` fail and the scan names it; conditional includes are invisible to the probe (one informational line, `status_conditional_includes`; doctor checks each repository). `GIT_DIR` and the other local variables are unset, `GIT_CONFIG_PARAMETERS`/`GIT_CONFIG_COUNT` stay, `GIT_DEFAULT_HASH`/`GIT_DEFAULT_REF_FORMAT` are unset; on Windows the repo path goes to native git as `C:/...`. No `cd`, every path absolute; a relative `GIT_CONFIG_GLOBAL` is read from status's own directory, only an absolute one is reliable. `status_hook_listing` exits with the subshell's status above 128 (130 on Ctrl-C). Only the first git counts; doctor reports a second old one.
- **Findings record**: doctor's one write; data, never sourced; merged under the lock from a fresh read; machine records and checked repositories are refreshed, an unreached repository's record goes only when proven gone (`doctor_rec_proven_gone`); doctor never writes what it cannot read (`doctor_rec_check_size`); per-line checks stay linear. Lock = symlink to the holder pid (Git Bash `ln -s` refuses a missing target, so the lock sets `MSYS=winsymlinks:sys` inline), stale when the holder is dead or the link is over a minute old; uninstall takes it before changing anything.
- **macOS**: `/bin/bash` 3.2 cannot parse the libs; `brew_cli_bootstrap` re-execs with two loop bounds; every install refusal uses `brew_unchanged_text`; the hook blocks on a non-empty `GNUBIN_DIR` that is not an absolute directory (docs/platforms.md#maintainer-notes). Git upgrade (`lib/gitup_macos.sh`, #32): `brew install|upgrade git` as the user via `gitup_macos_brew_run` (no refusal line of its own), through the core's offer alone (not the single formulae install); no takeover (SIP, `gitup_macos_takeover_unavailable`); `brew_git_shim_unusable` never runs a no-CLT `/usr/bin/git` shim.
- **Windows**: bash and `find` say `/c/dir`, native git `C:/dir`, `cmd` `C:\dir`: compare in one form (`cygpath -m -l`), never test a native-git path with `/*`. A running script pins its directory (`install_copy_share`), the lock wait is bounded in seconds, and the work dir ignores a `TMPDIR` outside `HOME`. The rest, with test names: docs/platforms.md#maintainer-notes.

## Git upgrade on RPM systems (story 28; behaviour: docs/install.md and docs/platforms.md#rhel-rocky-and-fedora-rpm, plug-in contract: CONTRIBUTING.md)

- **Shape.** `lib/gitup.sh` is the core (`gitup_os_class`, `gitup_registry` = a plain `case` with one reserved line per class and a comment line between them, or parallel branches conflict in a real merge; offers; `gitup_consent` prompts only when stdin and stderr are terminals, default No). `lib/gitup_rpm.sh` is the module, `lib/gitup_source.sh` the shared source route, `lib/gitup_takeover.sh` the takeover. A module = one file with `_plan MODE` and `_apply` plus one registry line; optional and all-or-none: the takeover set, `can_elevate`+`elevate`; optional singles: `takeover_unavailable`, `abort` (a wrapper module must forward it). `gitup_call` is the only place a function name is built. Tests use synthetic classes (`gu_tree_add_class`), never a reserved one.
- **Order.** `install_run` runs the refusable checks (state, config probe, `install_precheck_timer`) before the offers when git can run `config --show-scope` (>= 2.26), the offers, then the rest. The write probe removes a config file it created empty (`install_check_config_writable`, `lib/hookspath.sh`).
- **Privileged commands.** `gitup_plan_priv` and `gitup_elevate` resolve tools only with `gitup_system_bin` (`/usr/bin:/bin:/usr/sbin:/sbin`, root-owned, not group/other writable; never the caller's `PATH`; the build `PATH` is `/usr/bin:/bin`), under umask 022. The plan lists every command that can run, full path first, conditional ones marked `[only when ...]`; `check_plan_matches_log` (`tests/gitup.sh`) compares whole normalized commands of the plan with the sudo log.
- **dnf (probed, dnf 4.14 Rocky 9.7, dnf5 Fedora 44).** `dnf --assumeno -q repoquery --latest-limit=1 --queryformat '%{version}\n' git-core`, stdin from `/dev/null`, under a timeout, so an unimported key fails instead of prompting. `dnf install -y` can import a repository key; the plan says so. **Route rule (changed after story 28):** a repository the user cannot read does not decide the route when the readable ones were all read (`package` if one offers >= 2.54, root gets `--disablerepo=* --enablerepo=<id>` for each repository read, because dnf 4 hides a `.repo` file the user cannot read, so a deny list cannot cover it; `source` if none does); any parenthesised entry (list unreadable, budget used up, whole query failed with no repository named, nothing readable) means incomplete = `source`. dnf output stays in variables, never in a file. The count of the dependency install is a dry run `dnf --assumeno install` without `-q` (dnf 4 hides its table under `-q`; as a user dnf 4 refuses it).
- **Takeover.** `/usr/bin` holds six git-core files (three are relative symlinks, fixtures must copy that). `excludepkgs` must name every installed package of the source RPM (`git git-core git-core-doc perl-Git`): `git-core` alone breaks `dnf update` on dnf 4. The entry sits behind a marker comment that keeps the original line; `active` needs the real `excludepkgs` line (`gitup_tk_entry_present`, spaces or commas), not only the marker. Identity is link-aware (`gitup_tk_id`); saved originals are never replaced while a link of ours exists; the backup is built as `orig.new`/`record.new` and renamed; links by `ln -sfT` then `mv -T`; `dnf.conf` replaced by rename keeping its mode. One undo (`gitup_tk_restore_core`) serves rollback, interrupt and `restore-system-git`. States none/active/undone/broken; uninstall stops in every state except none; a broken record prints by-hand commands built from `orig/`.
- **Partly applied states are the contract.** Interrupted and killed takeovers and restores are tests (`gu_interrupt_run`: `sudo.stall` knob, signals only the process group it started with `setsid`, never `pkill -f`). A rebuild under an active takeover is refused; a `MANIFEST.partial` refuses the takeover.
- **Source route.** Downloads are verified before the first privileged command. `MANIFEST.partial` is saved before the copy and renamed after (`GITUP_KNOWN` all, `GITUP_DONE` finished, `GITUP_PARTIALS`); the "partly copied" clause goes into `GITUP_CHANGED` before the `cp` (an interrupt ends the shell) and is dropped after (`gitup_changed_drop`); `status`/`doctor` show an unfinished copy. `cp -dR --remove-destination --preserve=timestamps,links` without `mode` (it rewrote shared directory modes); `--remove-destination` because cp onto an existing symlink writes through it (a later pin could ship a builtin as a program over `bin/git`), and it replaces each hard link of an older build. `make` gets `INSTALL_SYMLINKS=1`: git's hard links tie `bin/git` to 150 libexec names, one inode that SELinux labels by whichever path `restorecon` visits last (`bin_t` becomes `usr_t`); `gitup_tk_check_owner` judges each link of a chain (owner, and a hop must stay in the prefix) and the final target (owner, and inside the prefix: a last component of `..` passes the hop test), not the 777 of a link. Only the programs of a finished MANIFEST get the `ldd` check (not all of `/usr/local/bin`). A failed build keeps `make.log` in `$TMPDIR/gsg-git-build-failed.*.log`.
- **Ctrl-C.** A bash script without a trap ignores SIGINT when the child it waits for survives it (`sudo`/`cp` finishing normally); `install` and `restore-system-git` trap INT/TERM/HUP (`gitup_tk_restore_stopped`: state, next command, work dir removed). The build runs under `timeout --foreground`. A random-timing SIGINT run of the takeover never showed an ignored signal.
- **Pins and seams.** `tools.lock` rows `git`/`git-manpages` `source` are not scanners (`GSG_TOOL_NAMES` never sees them). `GSG_GITUP_ROOT` moves `/usr/local`, `/usr/bin`, `/var/lib/git-secret-guard`, `/etc/dnf/dnf.conf`, `/etc/apt` into a sandbox (the current user becomes the trusted owner); `GSG_GITUP_BUILD_PATH`, `GSG_GITUP_QUERY_TIMEOUT`; all announced on stderr. `lc_begin` adds the `sudo dnf rpm restorecon make df ldd` stand-ins and user-owned exec wrappers of `cp rm mv mkdir install ln rmdir touch env`; force a root run with `gitup_is_root() { return 0; }` in `gu_run`, never a fake `id`. `tests/platform/rpm.sh rocky|fedora` needs `policycoreutils` in the image for `restorecon`.

## Git upgrade on apt systems (story 29; behaviour: docs/platforms.md#ubuntu-and-debian-apt, module `lib/gitup_apt.sh`)

- **Route rule.** distro candidate >= 2.54 = `package`; else Ubuntu class = `ppa` with the pinned source build as the fallback; Debian class = `source`. The release number never chooses (`test_ubuntu_2404_*`, `test_ubuntu_2204_*`, `test_a_ppa_that_lags_*`). A derivative with `ID_LIKE` ubuntu is the ubuntu class (`install_os_family`). The candidate comes from `apt-cache policy git` under `LC_ALL=C`, stdin `/dev/null`, `timeout -k 5 $GITUP_QUERY_TIMEOUT`, parsed in a here-string loop (never `sed ...q` under pipefail); `gitup_apt_upstream` drops epoch and suffix, and `2.54.0~rc1` is refused as a pre-release.
- **PPA order is a security rule** (`gitup_apt_ppa_apply` steps): tools (sps+gnupg only when `add-apt-repository` or `gpg` is missing), `add-apt-repository -y -n`, key check, `apt-get update`, candidate >= 2.54, `apt-get install`. Any failure disables (`gitup_apt_ppa_disable`: both file forms AND `trusted.gpg.d/git-core-ubuntu-ppa.gpg*`, which apt trusts for every repository) and refreshes apt before the source route. Disable or refresh failing = rc 2 = stop, no source build. `GITUP_APT_PPA_PENDING` + `gitup_apt_abort` disable an unchecked PPA on Ctrl-C.
- **Two file forms.** 24.04 writes `.sources` with the key embedded in `Signed-By:`; 22.04 writes `.list` and the key in `trusted.gpg.d/git-core-ubuntu-ppa.gpg` (20.04: `git-core_ubuntu_ppa.gpg`; proven by the WSL 1 chroot runs). The check reads both; a missing key file, a second key, an oversized file or no file at all is not the pin. Fingerprints are parsed from `gpg --show-keys --with-colons` records in bash (not awk after gpg: a failing gpg must not hide behind a pipe).
- **Non-interactive under sudo.** `sudo` drops the environment, so every apt command is `env DEBIAN_FRONTEND=noninteractive NEEDRESTART_MODE=a APT_LISTCHANGES_FRONTEND=none <apt-get> -o DPkg::Lock::Timeout=120 ... -y` (`gitup_apt_cmd`); the plan prints the same array it runs. Conditional lines carry `  [only when ...]` (two spaces) so `check_plan_matches_log` strips them; the source-build fallback lines are marked by `gitup_apt_plan_fallback` (it captures `gitup_source_print_plan` in a temp file because command substitution would lose the `GITUP_PRIV_CMDS` it fills).
- **Container script** `tests/platform/ubuntu-container.sh` sources the product libs and `install_git_ppa` is a wrapper over `gitup_apt_ppa_apply`; there is no second copy (`test_the_container_script_calls_the_product_for_the_ppa_and_holds_no_copy_of_it`). `--phase upgrade` = `apt-phase.sh` + `apt-upgrade-e2e.sh`; `ubuntu.sh --os ubuntu-24.04|ubuntu-22.04|debian-13` picks the pinned image and passes `--expect-os`. All three `--phase upgrade` runs and the default phases ran on hosted runners (record: docs/platforms.md#ci-on-real-platforms).
- **Tests.** `tests/apt.sh` holds the stand-ins (`apt-get`, `apt-cache`, `add-apt-repository`, `gpg`, plus an `env` exec wrapper; `lc_begin` installs them, they use `printf`, not `echo`: Ubuntu's `/bin/sh` is dash) and fixtures (`gu_apt_setup`, `gu_apt_fixture sources|list`, `gu_apt_without_sps`); knobs are files `apt.candidate`, `apt.ppa.candidate`, `apt.origin`, `apt.update.fail` (ppa|clean|any), `apt.fail`, `apt.add.rc|nowrite|hang|lock|nonopt|extra`, `apt.hang`, `apt.cache.fail|failafter`; a `STUBGARBAGE` line makes the gpg stand-in exit 2, and an input with no `STUBKEY` also exits 2 like the real tool. The stand-ins read an entry as active only on a non-comment line without `Enabled: no`. `gua_run`/`gua_reply` call module functions directly. `test_gitup_apt*.sh` skip on Windows like `test_gitup_rpm.sh` (the class there is `windows`); on a Windows host they ran in WSL against a copy of the tree with a static Linux jq (git 2.34 there, so no hook ever fires and the commit assertions live only in the container E2E).
- **Known limits.** Existing PPA state is recorded first (`gitup_apt_preflight`): files that pass the key check are kept and used as they are (no `add-apt-repository`, nothing removed on failure), files with another key go to a root-owned `ppa-aside-<UTC>` directory under `/var/lib/git-secret-guard` (named in the output, never deleted), entries under other names (found by content) stop the route. Real `add-apt-repository` keeps an existing entry and imports the key INTO the existing keyring (a merge, real gpg showed 2 keys), so a keyring holding the pin plus any other key is not the pin: apt trusts every key in it. Linux Mint's `add-apt-repository` has no `-n` (read from the mintsources source, not run): `gitup_apt_adder_ok` probes `--help` and the route falls back to source. `GITUP_SRC_PRE` (shared source lib) is the refresh before the dependency install; `GITUP_PRIV_BYHAND=0` makes the core tell a user without sudo to run install as root instead of listing commands that would skip the key and floor checks. The source route on Debian keeps the distribution `/usr/bin/git` (the other-git warning applies; no takeover on these classes). `libpcre2-dev` + `USE_LIBPCRE2=1` on Debian is not container-proven.

## CI on real platforms (`.github/workflows/platforms.yml`; behaviour and run record: docs/platforms.md#ci-on-real-platforms)

- **Not a PR check.** Hosted `ubuntu-24.04` runners, podman 4.9.3 rootless, `/dev/kvm` present. The workflow is `workflow_dispatch` only (`gh workflow run platforms.yml --ref BRANCH`); a branch may add a `push:` trigger while iterating and must not merge it. The concurrency group names the commit. A job log is readable only when the whole run is complete, so read the uploaded artifacts instead (`gh run download RUN -n NAME`).
- **Isolation baselines on podman 4.9.3.** It masks `/sys/dev/block` too (`maskedPaths` of its `config.json`); the one added rule is `/sys/dev/block=tmpfs` (`ISOLATION_MOUNT_RULES`). `/dev`, variables, namespaces and `/run/secrets` checks are unchanged. Nothing is skipped: `ubuntu.sh` must never mention `--skip-isolation`.
- **Rocky containers need `/etc/shadow` at 0400** (`rpm_fix_shadow`): at the image's 000 PAM cannot read it under this runner's rootless podman and every `sudo` fails ("PAM account management error"). The setuid bit on `unix_chkpwd` and `rpm --setcaps` did not help. A fixture, not a product change.
- **Phases beyond `upgrade`** (`ubuntu-container.sh` accepts `upgrade-root|password|bump|old|takeover|offline`, run by `rpm-phase.sh` through `rpm-more-e2e.sh MODE`, which sources `rpm-upgrade-e2e.sh`): root = no sudo on the machine; password = sudo on a `script` pty with a random password in a 0600 file (never printed, asserted absent); bump = git 2.55.0 pin then the current pin through an edited `tools.lock` in the checkout; old = Fedora 41's git-core 2.47.0 by pinned digest; `rpm.sh rocky --offline-restore` = stage 1 takes over, `podman commit`, stage 2 restores with `--network none`.
- **Rocky VM** (`rocky-vm.sh` host side, `rocky-vm-e2e.sh` guest): pinned dated GenericCloud qcow2 with its SHA-256, qemu `-display none` (`-nographic` cannot be combined with `-daemonize`), ssh forward on 127.0.0.1 only, guest script run under `bash -l` so `/usr/local/bin` is first on PATH as for a user. Without a writable `/dev/kvm` the launcher exits 3 and says what TCG costs unless `GSG_VM_ACCEL=tcg`.
- **Old git** (`old-git-e2e.sh`): a git below 2.54 ignores `hook.<name>.*` and commits a fake key without a word; measured with 2.45.3 built from its pinned tarball and with the git in GitHub Desktop 3.4.13's `.deb` (pinned digest).
- **Windows job** (`windows-gitup-e2e.ps1 -Scenario winget|inuse|inuse-winget|killed|signature|rerun|prompt`, `[win]`): installs Git for Windows 2.53.0.3 over the image's git with `/ALLOWDOWNGRADE=1` (fixture only), then runs the product. winget exists on `windows-2025`, so the installer-route scenarios remove it from `PATH` of the product process. Results and the three product fixes they led to (`PSModulePath` reset, `gsg-bash.cmd` half-installed message, runner exit 19 when programs of the Git directory run) are in docs/platforms.md#windows. The pty scenario is recorded as not possible (ConPTY returned no child text).

## WSL (story 31; behaviour: docs/platforms.md#wsl-windows-subsystem-for-linux)

- **Never run `wsl.exe`, `wsl` or `ubuntu.exe` on the Windows development host**: WSL 1 on Server 2019 blue-screened it twice in `lxcore.sys` (cause not established, docs/platforms.md). Real WSL runs are `.github/workflows/wsl.yml` (started by hand, hosted runner) with `tests/platform/wsl-ci.sh`; the product is tested locally through fixtures.

Detection reads kernel files as data (`lib/wsl.sh`, seams `GSG_WSL_*`, announced); `tests/test_wsl.sh` fakes `uname` and runs on Windows too.

## When to run which tests (every agent, every story)

- **While developing: targeted tests only.** After a change, run only the test files that cover it: `tests/run.sh tests/test_x.sh [tests/test_y.sh ...]` (Windows: `tests\run.cmd tests/test_x.sh`). A change to a shared helper (`lib/common.sh`, `tests/lib.sh`, `tests/lifecycle.sh`) means the files that use it, not the suite.
- **The full suite runs once, right before commit and push.** Run `tests/run.sh` with no arguments only at that point. Never run it after each edit, after each review round, or to check that nothing broke mid-task. A full run takes a long time and starves any other agent on the machine.
- **A failure in the full run:** fix it with the failing files alone, then run the full suite once more only if you are about to commit.
- **Reviewers and manual testers do not run the full suite.** They run the files they need to check a finding or a scenario. Report which files ran, and say that the full suite did not.
- **A skipped file proves nothing.** `tests/test_gitup_*.sh` skip on Windows, where the OS class is `windows`: run those on Linux or in WSL, and read the skip count before calling a change tested.

## Git upgrade on Windows (story 30; behaviour: docs/platforms.md#upgrading-git-for-windows)

- **Shape.** `lib/gitup_windows.sh` (class `windows`), `bin/gsg-gitup.ps1` (the runner), one pin row `git-for-windows 2.56.0.4 windows_amd64` in `tools.lock` (installer `Git-<v>-64-bit.exe`, tag `v<a.b.c>.windows.<n>`, never in `GSG_TOOL_NAMES`). Bash plans, downloads through `tools_fetch_verified` and writes `<handoff dir>/handoff.txt` (route, scope, version, installer; no digest); `gitup_windows_apply` returns 2, the core exits 3. **Bash never runs the installer or winget**: the upgrade replaces the bash it runs in. The runner (Windows PowerShell, outside bash) is started by `git-secret-guard.cmd` (checkout) and by the `.cmd` `install_cli_cmd_text` writes (`goto :handoff` when exit 3 and the file exists), or by hand from Git Bash with the command `gitup_windows_next_text` prints (with `GSG_INSTALL_FLAGS`). There is no loop because the `.cmd` is straight-line code: one runner call, one rerun of bash, then exit.
- **`GSG_HANDOFF`** (set by the `.cmd` to `%LocalAppData%\git-secret-guard\git-upgrade\handoff.txt`) is accepted only as `git-upgrade/handoff.txt` below `LOCALAPPDATA` (case-insensitive, no `..`); the state route gets the same name and link checks (`gitup_windows_handoff_place`, `gitup_windows_no_links`: MSYS shows junctions as links). The directory is emptied of `Git-*-64-bit.exe` and `handoff.txt*` only. The `.cmd` deletes a stale hand-off first and sets `GSG_GIT_UPGRADED=1` for its rerun (`brew_unchanged_text` then does not say "nothing was changed"); the runner deletes the hand-off before it starts anything and the installer after success; `uninstall_gitup_handoff` cleans both places.
- **Runner checks** (all before the start): SHA-256 equals the `tools.lock` pin and Authenticode is `Valid` with the subject of the `# gsg-signer` line of that lock (both read by the runner from the lock beside `bin`, `Get-Pin`); no reparse point on the installer or the two directories install made (`Find-ReparsePoint`, after the file is open with `FileShare.Read`; bash checks the same two, a link above them such as a moved profile is accepted). A file with another digest is deleted; a link or signature refusal keeps a file that matched its pin and says a rerun will not help. `Valid` does not prove the certificate unrevoked (cache-only revocation) and rests on the timestamp (the signing certificate expired 2026-10-27). Defended: a swapped or substituted installer, a self-vouching hand-off. Not defended: same-user code (it can edit the `.ps1`, `tools.lock`, the hand-off). Exits: 0, 10 refused, 11 declined (NativeErrorCode 1223 only, also inside an inner exception), 12 failed, 13 bad or used hand-off, 14 per-user from an elevated prompt, 15 other start failure, 16 unexpected, 17 installed version not older than the pin (stale hand-off), 18 non-empty installed version that does not parse (nothing ran; an empty one goes on), 19 programs of the install directory run (nothing ran, hand-off kept), 1 PowerShell refused. The version check follows the digest and signature checks and reads `Get-InstalledVersion` (one line, replaced by tests).
- **Scope.** `gitup_windows_detect` reads `reg.exe query HKLM|HKCU\...\Uninstall\Git_is1` (`Inno Setup: App Path`, `DisplayVersion`) from `System32` (`GSG_GITUP_ROOT/windows/System32` in tests); only the install holding the git on `PATH` counts. Elevation = mandatory label `S-1-16-12288` in `whoami /groups`. Machine scope from a normal prompt: `Start-Process -Verb RunAs`. No `/DIR`, `/LOADINF` or component flags: Inno's own `Inno Setup CodeFile:` values in the key are expected to carry options over (read on the host, **not** proven by a real upgrade). winget gets `--scope`; it is untested.
- **Hazard answer (real run, Server 2019, nothing else holding Git open).** The shell-replacement hazard is real and the hand-off design handles it: all bash processes end, the runner starts the installer, `-Wait` follows it and its helpers, `bash.exe` is replaced cleanly, then install reruns. `Git_is1` differed only in `InstallDate` and `etc/gitconfig` was byte-identical, so options carry over with no flags. A downgrade makes the installer stop on a Yes/No box under `/VERYSILENT` (never pass `/ALLOWDOWNGRADE`; the runner refuses with exit 17 instead). Not proven: files in use, a killed installer, winget, a real UAC decline, a typed yes. Git Bash puts its hand-off in `~/.local/state`, the `.cmd` in `%LocalAppData%`.
- **Test seams.** `tests/gitup_windows.sh` (`wu`, `wu_begin`, registry/`whoami`/`winget` stand-ins, a compiled console `.exe` signed with a throw-away certificate as installer, a fake `cygpath` on Linux). **The runner reads no environment** (a test asserts no `$env:`); tests run a sandbox copy with its own `tools.lock`, and `wu_runner_seam` changes exactly one line of the copy (the status, the one-line `Test-Elevated`). `wu_runner_shadow` wraps `Start-Process` to record the verb, hold between the checks and the start (`GSG_TEST_HOLD` belongs to the wrapper), or throw `Win32Exception(1223)`; its `norun` mode lets `test_real_the_pinned_installer_...` check the real cached asset against the unmodified product runner and lock. The signed stand-in is built once into the tools cache (`gsg-test-standin`) and its key and CA copy are deleted (`-DeleteKey`). Windows runs test files in parallel and they share the user's certificate store and key directory: every writer runs under `wu_with_cert_lock` (`wu_build_standin`; the safety tests use `wu_build_standin_unlocked` inside it), and the build records its own key file name (`key.name`), so never count the whole Keys directory (#77). Git for Windows' `bin\bash.exe` prepends its own git to `PATH`, so a fake old git cannot win inside a bash the `.cmd` starts: the `.cmd` tests copy the product and replace only `bin/git-secret-guard` by a small CLI running the real core and module, and one test runs the real CLI directly. A native `cmd.exe` mangles URL-like or path-like environment values (the test CLI exports what it needs itself) and `MSYS2_ARG_CONV_EXCL` would reach the bash below: use `cmd.exe //c`. A Windows path in a `sed` replacement hits `\U` (GNU case switch). Windows-only tests need an elevated prompt (`fltmc`), or a machine-wide run would show a UAC prompt.

## Testing tricks

- **The hook never sees a fake `git` on `PATH`** (git prepends its exec-path). Inject `setsid`/`timeout` through settings (`use_stubs "SETSID_BIN=..."`). To break only the hook's probe repo, point `GIT_CONFIG_GLOBAL` (`set_env`) at a copy plus `[includeIf "gitdir:<TMPDIR>/"]`; to break doctor's git, a wrapper failing `git -C /` with 128. `GIT_TEST_ASSUME_DIFFERENT_OWNER=1` simulates `safe.directory`.
- **Stand-ins** report configured findings whatever the tree holds: clear `STUB_GL_FINDINGS` between steps, assert on `STUB_RECORD`. A stand-in that must be killed needs `exec sleep`.
- **Signals**: background jobs start with SIGINT ignored, so INT tests launch git with `env --default-signal=INT`. Never `pkill -f` a pattern that is in your own command line.
- **Stdin socket quirk**: with a socket on stdin, `env -i ... bash -c` reads `~/.bashrc` and changes `type -P` answers; tool-lookup helpers (`dr_which`, `lc_which`, `lc_first_git_dir`) redirect stdin from `/dev/null`.
- **Old git**: compute expectations from `/usr/bin/git --version`; a fake old git goes after the real one on `PATH`.
- **On a Mac** always run `tests/run.sh FILE` (it puts the brew bash and gnubin first; plain `bash tests/test_x.sh` gets BSD tools). Real-scanner tests read `~/.cache/git-secret-guard-test-tools` (`tests/fetch-test-tools.sh`; also the Windows default).

## Conventions

- Coded comments (`# ^ tag clause`), sparse; definition and lint: `awk -f tests/comment-rules.awk FILE`. Tags: hazard coupled security invariant external order why see perf todo; `why X, not Y; reason`; <= 160 chars, <= 3 coded lines in a row; no ` so `, ` but `, ` because `, ` which `, ` that `, ` then `, ` while `, `: `.
- `set -u`; check every return value; bounded loops; files under 1000 lines; shellcheck clean (info included) at `GSG_SHELLCHECK_PIN` 0.11.0 (other versions skip the gate). A local named like a sourced array (`lines`) trips SC2178/SC2128. Names must not be confusable (`INSTALL_TIMEOUT_BIN` is a path, not a duration).

## Correct as written: do not "fix"

- `wait "$!"` after `done < <(find ...)` or `mapfile < <(git ...)` returns the substituted command's status (bash 4.4+); a process substitution as stderr filter would race, hence pipe + `PIPESTATUS`.
- `${v%"${v##*[!/]}"}` trims all trailing slashes; `type -aP git` is valid; `A=0 B=""` alone on a line sets both; `${kv#*$'\n'}` needs its guard for valueless records.
- `doctor_unreadable` returning 1 means "not explained by permissions" (caller exits 2); `$key` in `doctor_repo_info` is the absolute common dir.
- A token in a remote URL path can appear in `EXEMPT_GIT_ERR` on the user's own stderr: accepted, it is the user's config shown to the user.
- `/proc/self/mountinfo` field 5 is the mount point, fstype follows the lone `-`; `awk -F: '$1 == "fpr" {print $10}'` is right for `gpg --with-colons`.
- `lib/extract.awk` writes nothing to stdout, so `2>&1 |` into the sanitizer swallows no extracted lines.
- Doctor's git shim omits `--foreground` on purpose; the hook adapters keep it on purpose. The one `git hook list` bound of `status` and doctor's machine section (`hooklist_bind_timeout`) also keeps it: that call starts no child, so the shim's reason (a timeout must reach the whole group) does not apply, and without it Ctrl-C would not reach git.

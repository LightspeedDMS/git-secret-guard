# git-secret-guard: project notes

Bash tooling (no Python/Node). Epic and stories are GitHub issues in LightspeedDMS/git-secret-guard (epic #1; stories #2 scan 01.01, #3 exemptions 01.02, #4 lifecycle 02.01, #5 doctor 03.01, #6 Ubuntu 04.01, #7 migrate this machine 05.01). User-facing docs: `README.md` is the short overview; the detail is in `docs/{install,platforms,scan,exemptions,doctor}.md`.

## Layout

- `hooks/secret-scan`: entry point git runs as `hook.git-secret-guard.command`. Reads `<share>/settings`, where `<share>` is two levels above the resolved script path.
- `lib/common.sh` (settings, `tool_unusable`, jq cleaner), `lib/extract.sh` + `lib/extract.awk` (staged diff to scan tree), `lib/exempt.sh` (everything about in-repo exemptions: `.secret-scan-ignore` parser, catch-all scope, HEAD blob reader, gitleaks pre-flight: config load plus built-in-rule probe; the doctor story reuses `scan_ignore_parse` and `scan_ignore_scope`), `lib/report.sh` (merge and print), `lib/scanners/{trufflehog,gitleaks}.sh` (`scan_<tool> <scan_dir> <abs out_dir>` writes `<tool>.rows` and `<tool>.errors`), `lib/run-scanner.sh` (what the hook starts per scanner, under `setsid`).
- `bin/git-secret-guard`: the CLI (`install [--replace-hooks-path] [--with-timer]`, `uninstall [--remove-tools]`, `status`, `doctor [--roots DIR...]`, `version`, `help`). Installed as a symlink in `~/.local/bin`; `GSG_ROOT` is two levels above its `realpath`, in a checkout and in the share dir alike. Help text is `lib/usage.md`. Lifecycle libs, **install-time only** (the hook never loads them; `test_the_hook_never_loads_the_install_time_libraries`): `lib/state.sh` (paths from HOME/XDG, state file), `lib/tools.sh` (`tools.lock` parser, platform names, URLs, download + SHA-256 + extract), `lib/hookspath.sh` (`lifecycle_read_hooks_path`, the one reader of the global `core.hooksPath` shared by install, uninstall and status), `lib/install.sh`, `lib/uninstall.sh`, `lib/status.sh`, `lib/timer.sh` (systemd user unit texts, marker, target checks, atomic writer), `lib/doctor.sh` (run, machine checks, output) and `lib/doctor_repos.sh` (discovery and per-repo checks). The CLI also sources `lib/exempt.sh` for doctor; the hook never loads any of the lifecycle, timer or doctor libs (`test_the_hook_never_loads_the_doctor_and_timer_libraries`). `tools.lock` and `VERSION` are shipped data.
- `tests/run.sh` runs `tests/test_*.sh`; `tests/lib.sh` is the harness; `tests/stubs/{trufflehog,gitleaks}` are stand-ins driven by `STUB_*` env vars; `tests/fixtures/husky/h` is husky 9.1.7's real `h` (MIT, verbatim).
- `tests/lifecycle.sh` = helpers for the lifecycle suites (`test_install`, `test_uninstall`, `test_status`, `test_tools`, `test_cli`, `test_lifecycle_e2e`, `test_install_network`): `lc_begin` wipes the sandbox HOME/XDG/gitconfig, `gsg` runs the checkout's CLI under `env -i`, `lc_make_fixtures` builds fake tool tarballs plus a matching lock, `lc_use_fixtures` points the download override at them, `lc_path_without TOOL` builds a PATH of symlinks minus one tool, `lc_git_wrapper '<sh condition>'` puts a `git` first on PATH that fails only the calls matching the condition (and execs the real git otherwise), `lc_real_lookup` + `gitreal` drop `GIT_CONFIG_GLOBAL` and set `XDG_CONFIG_HOME` so git's own `~/.gitconfig` / XDG / include lookup runs against the scratch HOME (`tests/test_hookspath.sh` uses them). `tests/test_upgrade.sh` holds the pin-bump and failure-injection tests (`bump_pins` rewrites `fixture.lock`, a fake `install` on PATH fails the staging copy of one tool). It makes `configure_hook` a no-op, so no hook config is pre-seeded.
- `tests/doctor.sh` = helpers for the doctor suites (`test_doctor.sh`, `test_doctor_repos.sh`, `test_doctor_exempt.sh`, `test_doctor_gitleaks.sh`, `test_doctor_info.sh`, `test_doctor_readonly.sh`): `dr_begin` installs from the fixtures into the sandbox, `dr_repo NAME` makes a repo (initial commit with `--no-verify`) under `$SANDBOX/roots`, `doctor` runs the CLI with `--roots`. `tests/test_timer.sh` covers `--with-timer`. `lc_begin` puts a recording `systemctl` stand-in (`lc_systemctl_standin`: logs to `$SANDBOX/systemctl.log`, fails when `$SANDBOX/systemctl.fail` text occurs in the arguments) first on every lifecycle PATH, and `lc_path_without` links it into its farm, so no test can reach the real user manager.
- `tests/coverage.sh` = xtrace line coverage of the shell code (`lib/extract.awk` is not measured).
- Story 04.01 (Ubuntu): `tests/platform/{ubuntu.sh,ubuntu-container.sh,ubuntu-e2e.sh}` (the podman run, not part of `tests/run.sh`), `tests/test_platform.sh` (the run's command line via `--dry-run`), `tests/test_awk_portability.sh` (mawk against gawk), `tests/test_prerequisites.sh` (install hints). `GSG_TEST_GIT` overrides the git the suite drives (default `/usr/local/bin/git`); see "Portability and follow-ups".

## Facts that cost time to find

- **Config hooks need git >= 2.54.** `/usr/local/bin/git` is 2.56; `/usr/bin/git` 2.52 ignores `hook.<name>.*` silently. Tests call `/usr/local/bin/git` explicitly (`GIT` in `tests/lib.sh`). Config hooks run from the repo root before the hookdir hook, both run even if the first fails, and the commit is blocked if either fails. `--no-verify` skips them. A repo-local `hook.git-secret-guard.enabled=false` or `.command` wins (last value parsed).
- **Tool paths come only from the settings file.** `load_settings` unsets `TRUFFLEHOG_BIN`, `GITLEAKS_BIN`, `JQ_BIN`, `SETSID_BIN`, `TIMEOUT_BIN`, `SCAN_TIMEOUT_SECONDS` before sourcing it, so an inherited variable can never fill a gap. The hook validates all five with `tool_unusable` (absolute + executable, else it blocks with "nothing was scanned"); the adapters and `gitleaks_config_preflight` call `"$TIMEOUT_BIN"`, the hook calls `"$SETSID_BIN"`. No `PATH` lookup for those five (`bash` through the `#!/usr/bin/env bash` shebangs, `git`, `awk`, `sed`, `cp`, `rm`, `mkdir`, `mktemp`, `realpath`, `find` and the other coreutils DO resolve through `PATH`; git prepends its exec-path for hooks; the shebang is deliberately not pinned, `docs/scan.md` says so; `test_the_docs_do_not_claim_the_hook_has_no_PATH_lookup`). `test_the_hook_never_looks_tools_up_on_PATH` greps every lib except `lib/install.sh`, where `type -P` at install time resolves `jq`, `setsid`, `timeout` into the settings file.
- **`<share>/settings` is generated by `install`** (`install_write_settings`, `printf %q` quoting since the hook sources it) and rewritten by every install; `tests/lib.sh:write_settings` writes the same keys for the hook suites (`TEST_SETSID`/`TEST_TIMEOUT`, overridable with `GSG_TEST_SETSID`/`GSG_TEST_TIMEOUT`).
- **Test isolation.** Every test file gets a sandbox under `~/.tmp/git-secret-guard-tests.XXXXXX` with scratch `HOME`, `GIT_CONFIG_GLOBAL=<scratch>`, `GIT_CONFIG_NOSYSTEM=1`, `env -i`. The real `~/.gitconfig` has `core.hooksPath=~/.config/git/hooks`; it must never apply, and nothing under `~/.config/git` is ever touched. The hook config in the scratch global file is reset before each test (a test that breaks `.command` must not leak). `PYTHONUSERBASE` points at the real `~/.local` because `pre-commit` is a `pip --user` install.
- **Fake secrets are built at runtime** from fragments (`fake_aws_key`, `fake_github_token` in `tests/lib.sh`); `tests/test_quality.sh` scans the project tree with the real tools to prove no credential-looking literal is committed. Leak tests use a unique marker and assert it is absent from stdout and stderr.
- **trufflehog 3.99.2 exits 0 on unreadable input** even with `--fail-on-scan-errors`; it only logs an error-level JSON line. So error-level lines count as scan errors, and only their `msg` is printed (structured fields can carry verifier URLs holding the candidate). Findings exit 183. `tests/test_real.sh` pins the exit-0 behavior and fails loudly if a newer trufflehog changes it.
- **trufflehog "unknown" vs "unverified".** With network, a rejected fake credential is `unverified` and is hidden by `--results=verified,unknown`. A dead proxy (`HTTPS_PROXY=http://127.0.0.1:9`) makes verification fail, so the same candidate becomes `unknown` deterministically; the real-binary tests use that instead of the network.
- **gitleaks 8.30.1 exit codes (verified, `test_real_gitleaks_exit_code_semantics_8_30_1`).** Clean: 0 and report `[]`. Leaks: `--exit-code` value. Default leak code is 1, and a fatal error (bad config) is also 1 with no report, so the adapter uses `--exit-code 42`. A missing target or an unreadable file logs `WRN skipping ...` and still exits 0 or the leak code, so skipped files are errors.
- **gitleaks reads `<target root>/.gitleaksignore`** even when `--gitleaks-ignore-path` points elsewhere (probed; nested files and the cwd copy are not read). A commit adding that file could mute itself, so the adapter runs gitleaks on a copy where it is renamed `.gitleaksignore.gsg-committed`. An explicit `--config` beats a committed `.gitleaks.toml`.
- **gitleaks runs with cwd = scan dir and path `.`** so `File` and `Fingerprint` are repo-relative (`src/a.txt:aws-access-token:4`), the form a committed `.gitleaksignore` needs (story 01.02). With an absolute path the fingerprint embeds the random temp dir.
- **Extraction.** Sparse files: added line N at line N, all other lines blank (trufflehog line numbers stayed exact across chunks at line 20001). Diff flags are fixed and explicit so user diff config cannot change the parse. Git C-quotes odd names; the awk unquotes and refuses `..`, `.`, empty components and absolute paths (exit 2, the hook blocks). Binary files and `-diff` attributes yield no `+` lines, so nothing is passed on.
- **A committed `.gitattributes` must not decide what is scanned.** `staged_diff` runs `git --attr-source=<empty tree>` (id from `git hash-object -t tree /dev/null`), otherwise `* -diff` or `*.txt binary` in the same commit hides added text from both tools (reproduced with the real binaries). `$GIT_DIR/info/attributes` and the system-wide attributes file still apply under `--attr-source` (probed, git 2.56) and are documented as a limit; `core.attributesFile` (and the XDG default) is pinned with `-c core.attributesFile=/dev/null`. `GIT_ATTR_SYSTEM`/`GIT_ATTR_GLOBAL` exist in the binary but did not change anything in a probe; the system file lives in root-owned `/usr/local/etc`, so it cannot be tested.
- **Signals.** Each scanner runs as `setsid bash lib/run-scanner.sh ...`, so the runner pid is its process group id; `cleanup` in the hook does `kill -TERM -- -pid`, `wait`, a bounded poll, then KILL, and only then removes the work dir (a surviving `cp -a` could otherwise re-create files holding the added lines). Adapters call `timeout --foreground`; plain `timeout` makes its own process group, which the group kill misses. A background job starts with SIGINT ignored, so tests that send INT launch git with `env --default-signal=INT`. Never `pkill -f` a pattern that also appears in your own command line.
- **trufflehog completion.** Exit 0 or 183 only counts with a `{"msg":"finished scanning","chunks":N}` log line, `N >= 1` (probed on 3.99.2: blank-only content gives 1, an empty tree gives 0). `/bin/true` as `TRUFFLEHOG_BIN` is therefore an error, like a missing gitleaks report.
- **gitleaks log lines.** Only the message words of ERR/FTL/`WRN skipping` lines are printed, cut at the first `key=value` word (fields can hold the candidate); a log over 5000 lines is an error instead of being truncated. gitleaks' default config skips whole paths (`node_modules/`, lockfiles, images, `go.sum`, ...): list and test in `docs/scan.md` and `tests/test_real.sh`.
- **Extraction is strict.** The awk dies on a line inside a hunk that is not `+`, `-`, space or backslash, and on a diff that ends before the hunk counters reach 0.
- **Exemptions are read from HEAD only** (`exempt_head_blob`: `git ls-tree --full-tree HEAD -- <path>`, then `git cat-file blob`), for `.secret-scan-ignore`, `.gitleaks.toml` and `.gitleaksignore`. No HEAD commit (`rev-parse` exit 1) or no entry: no exemption. Anything else blocks: a read error, a directory, a gitlink, and a **symlink** (it would read as its target text, so a one-line symlink could carry a catch-all). Only modes 100644 and 100755 are accepted. The hook materializes the two gitleaks files in the work dir as `repo-gitleaks.toml` / `repo-gitleaksignore` (names in `lib/common.sh`); the adapter uses them if present. Tests: `tests/test_exemptions.sh` (stand-ins), `tests/test_exemptions_real.sh` (real binaries).
- **Pathspec semantics (git 2.56, probed).** Patterns become `:(exclude,top,glob)<p>`. `top` is needed: without it git aborts on `/x` and `../x` ("outside repository") and `.` excludes everything. In `glob` mode `*` does not cross `/` (so `*` excludes only top-level files, `*/**` only nested ones), `**` / `**/*` / `**/**` exclude everything, a plain name excludes the subtree below that path, `**/` and `[` exclude nothing, malformed globs never make git fail. The parser strips leading `/` and `./` and rejects `..` components (they silently match nothing).
- **Pathspec excludes cannot be re-included**, so with excludes present `exempt_extract_tree` runs two diffs: everything except the ignore file with the excludes, then the ignore file alone. Without excludes it is the single original diff.
- **Catch-all detection** (`scan_ignore_scope`) builds a throwaway repo (`git init --template=` under the work dir) holding probe paths at several depths and name shapes, then asks git's own `diff --cached --name-only` which probes the production pathspec leaves. whole = none left; top = only nested left; nested = only top-level left. Local git env (`git rev-parse --local-env-vars`: `GIT_INDEX_FILE` is set during `commit -a`) is unset for the probe, or it would write into the real index.
- **gitleaks config semantics (8.30.1, probed).** A `--config` without `[extend] useDefault = true` runs ONLY its own rules: a bare AWS key ID stops being reported, and a config with no rules detects nothing and exits 0. **The "built-in rules are off" warning is behavioural, never a TOML read.** A table-aware awk was tried and was unsound both ways (E2E, real gitleaks): `x = """\n[extend]\nuseDefault = true\n"""` (text inside a multi-line string) turns the defaults OFF with no warning, while `[Extend]`/`UseDefault`, `[EXTEND]`/`usedefault`, `extend = { useDefault = true }`, `extend.useDefault = true` and `"extend".useDefault = true` keep them ON but warned. `gitleaks_config_preflight` scans a probe file holding `gitleaks_probe_secret` (an AWS key ID built from fragments, file `gsg-probe-builtin-rule`) in the same run as the load check; exit `GSG_GITLEAKS_LEAK_RC` (42) = reported = no warning, exit 0 = not reported = warning (missing `useDefault`, a global allowlist covering the probe, `disabledRules`), anything else blocks. A repo rule that itself matches an AWS key ID counts as detected (accepted; the check is behaviour, not rule ids). Cost measured (3 rounds of 40 calls): 45.7 to 47.0 ms with the probe, 47.2 to 48.8 ms without; no extra process, no measurable cost. Tests: `test_real_every_spelling_that_keeps_the_default_rules_prints_no_warning`, `test_real_a_use_default_setting_hidden_in_a_multi_line_string_still_warns`, `test_real_an_allowlist_that_covers_everything_also_warns_that_the_built_in_rules_are_off`. A staged root `.gitleaksignore` is still renamed in the copy; HEAD's is copied to `<ignore_dir>/.gitleaksignore`. A fingerprint `<path>:<rule>:<line>` suppresses exactly that finding (same file other line and other file same line stay).
- **gitleaks `[extend] path` is a hole, so the hook refuses it** (8.30.1, probed). The path resolves against gitleaks' cwd, which is the scan tree of added lines, not the config's directory, and absolute paths are read too; `path` together with `useDefault` is fatal; `extend.url` is ignored. A HEAD config extending `.gitleaks.toml` made a staged `.gitleaks.toml` with an allowlist mute an AWS key (exit 0, commit created). **A regex detector was tried and was unsound**: gitleaks treats key and table names case-insensitively, a multi-line string can hide a `[` line, `"path"` is the key `path`, and `"extend".path`, `Extend.Path` and inline tables with other casing all work (13 spellings slipped through). So `gitleaks_config_preflight` asks gitleaks itself: it runs the HEAD copy with cwd = an EMPTY directory (`$work/preflight/empty`, scan tree not yet created) and the probe directory `$work/preflight/probe` as the target, under `SCAN_TIMEOUT_SECONDS`; any non-zero exit blocks, showing only `msg_words` of the first ERR/FTL line. Relative paths (including `../scan/...` and `/proc/self/cwd/...`) cannot resolve there. Residual: an absolute path to an existing file outside the scan tree still loads (accepted, local HEAD config). Tests: `test_real_every_spelling_of_extend_path_is_refused` (22 spellings, each with a control run the old way), `test_real_an_absolute_extend_path_to_an_existing_file_still_loads_a_documented_residual`. The stand-in gitleaks treats an invocation without `--report-path` as the pre-flight (`STUB_GL_PREFLIGHT_RC/ERROR/SLEEP`): it logs the target's files to `STUB_LOG` and, without `STUB_GL_PREFLIGHT_RC`, exits 42 when the config holds a `useDefault = true` line (probe reported) and 0 otherwise; only the real-gitleaks tests settle what a config means.
- **Replace refs.** `git replace <HEAD commit> <other commit>` makes plain `git ls-tree HEAD` and `git diff --cached` use the other commit's tree, so a permissive `.secret-scan-ignore` or `.gitleaks.toml` outside the branch history became the exemption (reproduced with real tools: both a substituted catch-all and a substituted allowlist let a finding through). The hook exports `GIT_NO_REPLACE_OBJECTS=1` next to the pathspec unsets; the doctor story must do the same before reading HEAD. Test helper: `replace_head_with_permissive_commit` in `tests/lib.sh`.
- **gitleaks colours FTL lines even with `--no-color`** (8.30.1: `ESC[31mFTL ESC[0m ESC[1mFailed to load config ESC[0m ESC[36merror=...`), while WRN lines stay plain. A match on `ERR|FTL` must run `strip_ansi` first (`lib/common.sh`); both `gitleaks_config_preflight` and `gitleaks_log_errors` do, and `msg_words` then cuts at the first `key=` word so the `error="..."` field stays hidden. `gitleaks_config_preflight <conf> <work> <timeout>` (rc 0 probe reported, 2 loads but probe not reported, 1 block) takes the timeout explicitly and refuses a missing or non-positive one, so the doctor can call it. `scan_ignore_parse` rows are `LINE<TAB>pattern<TAB>as-written` (the third column keeps a leading `/` or `./`, so the catch-all warning quotes what the user typed) and its complaints carry the `git-secret-guard:` prefix like every hook message.
- **Config sweep for the diff text (R2).** `core.bigFileThreshold` below a file size makes git call the file binary and show no `+` lines (`git -c core.bigFileThreshold=1 commit` was enough to commit a token silently); pinned with `-c core.bigFileThreshold=100g`. A command-line `-c` beats repo config, `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT` (probed). `tests/test_inherited_config.sh` sets 28 settings in all three forms; only `core.bigFileThreshold` and `core.attributesFile` changed anything. Add a key there when you find a new one.
- **Comment lint** (`tests/comment-rules.awk`, run by `test_every_comment_follows_the_coded_comments_rules`, fixtures in `test_the_comment_lint_flags_each_planted_violation`): tag must be one of hazard coupled security invariant external order why see perf todo; `why` needs `, not <alternative>`; a trailing comment is an unquoted `#` at word start (quote state carries across lines, heredoc bodies are skipped); `.awk` files get only the full-line checks.
- **Inherited pathspec variables.** `GIT_LITERAL_PATHSPECS` (also set by `git --literal-pathspecs`) makes `:(exclude,glob)...` and `:(top,literal)...` match nothing, so every diff is empty and the commit passes unscanned. The hook unsets the four `GIT_*_PATHSPECS` variables right after loading the libs. `GIT_GLOB_PATHSPECS` with `GIT_NOGLOB_PATHSPECS` makes git fatal. `GIT_DIFF_OPTS`, `GIT_EXTERNAL_DIFF` and diff config (context, mnemonicPrefix, noprefix, renames, algorithm, relative, ...) do not change the extraction (pinned by `test_other_inherited_git_settings_cannot_change_what_is_extracted`).
- **Union check.** Per-pattern probes cannot see that `**/*[!t]` plus `**/*t`, `**/[!a]*` or `src/** lib/**` cover a tree. `_warn_if_union_covers_tree` counts `git ls-files -z --cached` with and without every exclude (ignore file left out of both); zero remaining warns. `exempt_report_exclusions` adds a warning when every staged file with added lines is excluded. The probe repo is built lazily and only for patterns containing `*`, `?` or `[` (1000 plain patterns used to cost about 5 s).
- **`git commit --amend` limit.** The hook environment (`GIT_*`) and the repository state are identical for an amend and an ordinary commit (probed), so an amend that adds an exempted file to the commit holding the ignore file cannot be told apart; documented and pinned by `test_amend_can_fold_an_exemption_and_the_exempted_file_into_one_commit_a_documented_limit`.
- **Never dump the environment in a probe hook.** `env` in a scratch hook printed real API keys into the session; log only `GIT_*` under `env -i`.
- **Inline markers (probed with the real binaries, fake GitHub token, dead proxy).** `trufflehog:ignore` on the line mutes trufflehog only, `gitleaks:allow` mutes gitleaks only, both on one line in either order mute both. A marker on the previous line mutes nothing.
- **Testing tricks.** git prepends its own exec-path to `PATH` for hooks, so a fake `git` on `PATH` is never reached by the hook. A fake `setsid` or `timeout` is injected through `SETSID_BIN`/`TIMEOUT_BIN` in the settings (`use_stubs "SETSID_BIN=..."`, see `test_a_signal_before_the_runner_has_its_own_group_does_not_wait_for_the_scan`); a poisoned `PATH` proves they are not looked up there. To break only the hook's probe repo, point `GIT_CONFIG_GLOBAL` (via `set_env`, per test) at a copy of the scratch config plus `[includeIf "gitdir:<TMPDIR>/"]`; a bad global value would also break the commit itself. The stand-ins report their configured findings whatever the scan tree holds: clear `STUB_GL_FINDINGS` between steps and assert on `STUB_RECORD` for what was scanned.
- **Parallel stand-ins must not share files.** `STUB_RECORD` gets a per-tool suffix; two tools appending to one file interleave.

## Lifecycle facts (story 02.01)

- **Release tarballs** (verified against the real downloads, `test_install_network.sh`): `trufflehog_<v>_linux_{amd64,arm64}.tar.gz`, `gitleaks_<v>_linux_{x64,arm64}.tar.gz` under `github.com/<owner>/<tool>/releases/download/v<v>/`. The vendors name x86_64 differently (`amd64` vs `x64`). Members: the binary, `LICENSE`, `README.md`. `--version` output: `trufflehog 3.99.2`; `gitleaks --version` = `gitleaks version 8.30.1`, `gitleaks version` = `8.30.1`. `tools_version_matches` accepts the pin only as a whole word (or `v<pin>`), so `3.99.20` and `13.99.2` fail.
- **Download override is test-only and cannot skip verification.** `GSG_TOOLS_BASE_URL` (directory URL, flat tarball names) and `GSG_TOOLS_LOCK` (lock file) are announced on stderr (`TEST OVERRIDE active`). `tools_fetch_verified` always compares the SHA-256 with the lock row (`test_the_base_url_override_cannot_skip_verification`: real lock vs fixture tarballs, wrong hashes, tampered tarball, empty lock, lock without the platform row, missing lock). A mutation check (comparison replaced by `if false`) made 3 tests fail. Without the base-URL variable curl runs `--proto =https --proto-redir =https`; with it `=https,file` for the first request only.
- **Install order** (everything refusable runs before anything changes): paths, git >= 2.54, warnings for other old gits, `type -P` of jq/setsid/timeout, platform, `core.hooksPath` read + refusal, CLI link check, hooksPath resolution, **global-config write probe**, state read, tool plan from the lock, download + verify + extract + `--version` check of every needed tool into a `mktemp -d` stage dir (a bad second tool installs neither), hooksPath backup, move tools into `~/.local/bin`, **state**, share tree (built beside the share dir with its `settings`, then two renames), CLI symlink, `git config --replace-all` of event + command, unset `core.hooksPath`. State is written before the config so an interrupted install can still be uninstalled.
- **git config exit codes that shaped the code** (git 2.56): a plain `git config --global key value` exits 5 when the key already has several values (`--replace-all` is needed, `--add` would duplicate); `--get-all` exits 1 for an absent key; `git config --global --list` exits **128 for a missing file as well as for a directory**, so it cannot detect "unwritable" (a fresh machine has no file). `install_check_config_writable` sets and removes a throwaway `gsg-install-probe` section instead. `--get-all` on a directory used as `GIT_CONFIG_GLOBAL` exits 1, as if the key were absent. `--type=path` expands `~` and `~user` (an unknown user is an error, so the takeover refuses); the stored value is read with `-z --get-all` and kept verbatim (`~/...` is not expanded in the state).
- **State** (`${XDG_STATE_HOME:-~/.local/state}/git-secret-guard/state`, mode 600 in a 700 dir): the five lines `version`, `previous_hooks_path_set` (`yes`|`no`), `previous_hooks_path` (verbatim, may be empty), `tools_installed_by_us` (space separated), `backup_path`, plus the optional sixth `tools_replaced` (space separated `<tool>.gsg-replaced-<UTC stamp>:<sha256 of the file install placed>`; and the optional seventh `tools_placed` (space separated `<tool>:<sha256>`, the file install last placed per tool; a tool has TWO words between the state write and the end of `install_commit_tools`, old and new hash, see the F2 paragraph). A state with five or six keys written before is still read; `state_write` always writes eight: the eighth is `timer_installed=yes|no`, optional on read, story 03.01). `state_read` refuses anything else (unknown, duplicate or missing required key, a bad flag, over 100 lines). **A recorded hooksPath is never overwritten; `no` is replaced by a real value taken over later** (`test_a_hooks_path_taken_over_after_a_plain_install_is_recorded`: this reads the story's "only if state has none yet" as "no recorded value", otherwise uninstall would lose the pointer). **When the state records a value and the current global value differs, install refuses before any change** (`install_check_recorded_hooks_path`, `test_a_second_takeover_with_a_different_value_is_refused_and_changes_nothing`; it used to print "recorded" while keeping the first value and pointing `backup_path` at the second tarball). ## Doctor and timer facts (story 03.01)

- **`git hook list pre-commit` (git 2.56, probed).** Prints `git-secret-guard` for an effective config hook, `disabled<TAB>git-secret-guard` for `hook.git-secret-guard.enabled=false`, `event-disabled<TAB>git-secret-guard` for `hook.pre-commit.enabled=false`, and `hook from hookdir` for the hookdir hook. With nothing configured it exits **1** with `warning: no hooks found for event 'pre-commit'` on stderr: that is an empty list, not a failure (`doctor_repo_hook` treats rc 1 plus that text as empty and every other non-zero rc as a PROBLEM). A local `hook.git-secret-guard.event=pre-push` ADDS an event, it cannot remove the global one.
- **Config records.** `git config --show-scope --show-origin -z --get-regexp` = `scope NUL origin NUL key NL value NUL`; a valueless key is only `key` (`doctor_split_record` gives an empty value, never the key). A repository-local origin is printed **relative to the cwd** (`file:.git/config`); `doctor_origin_text` makes it absolute. The last record of a key is the effective one. A key set through `[includeIf "gitdir:..."]` shows the included file as its origin with scope `global`.
- **Severity decision.** Exit 1 = at least one PROBLEM; WARNING (old git, catch-all, built-in rules off, unfinished placement) and info never change the exit status. Reason: `/usr/bin/git` 2.52 is reachable on this machine for good, so a warning that exited 1 would make "healthy" impossible here. The summary counts a repo as covered when it has no PROBLEM and prints `warnings: N` when any exist.
- **Discovery.** `find ROOT -maxdepth 4 -name node_modules -type d -prune -o -name .git -prune -print0` (repo at most 3 levels down). Grouping key = `rev-parse --path-format=absolute --git-common-dir`; a linked worktree has `--git-dir != --git-common-dir`. Two separate `rev-parse` calls, because a directory name may hold a newline (one two-line answer cannot be split). `wait "$!"` after `done < <(find ...)` returns find's real status (probed 7, 3, 1 on bash 5.1.8); `find` runs under `LC_ALL=C` and, when it fails only with `Permission denied` lines, `doctor_unreadable` names the directories with a second `find -readable/-executable` (never by parsing the messages), they are listed as PROBLEM and doctor goes on (exit 1, see "Review round 1"); any other `find` failure is still exit 2. Bound: 2000 `.git` entries (`GSG_DOCTOR_MAX_ENTRIES`, tested through a direct `doctor_discover` call with a lower value).
- **Reuse, not copies.** `exempt_warn_rows` (new, in `lib/exempt.sh`) is the loop the hook's `_load_ignore_file` and doctor both run; `GSG_MSG_BUILTIN_RULES_OFF` is the one built-in-rules sentence; `tools_probe_version` (status and doctor), `settings_tool_bin`, `install_collect_gits` (install's old-git warning and doctor). Doctor's PATH-dependent git listing therefore lives in `lib/install.sh`, the only place that may look tools up.
- **Pre-commit framework shim.** `pre-commit install` writes `# File generated by pre-commit: https://pre-commit.com` as line 2 of `<common-dir>/hooks/pre-commit` (pre-commit 4.3.0); doctor looks for that line in the first 5.
- **Doctor environment.** Before any HEAD read it exports `GIT_NO_REPLACE_OBJECTS=1` and `GIT_OPTIONAL_LOCKS=0` and unsets the four `GIT_*_PATHSPECS` plus everything in `git rev-parse --local-env-vars` (`GIT_DIR` from a calling hook would pin every check to one repo; `test_an_inherited_git_dir_cannot_point_every_check_at_one_repository`). That list includes `GIT_CONFIG`, `GIT_CONFIG_PARAMETERS` and `GIT_CONFIG_COUNT`, so doctor never sees a switch-off exported in the caller's shell (probed; a test cannot break `git config` through `GIT_CONFIG_COUNT`, it uses a `git` wrapper that fails `git -C /` calls with 128). A broken global config makes `rev-parse` itself fail: `git cannot start the checks (...)`, exit 2. Its only scratch is `mktemp -d` under `$TMPDIR` (or `/tmp`), removed on exit.
- **Timer.** Units `git-secret-guard-doctor.{service,timer}` in `${XDG_CONFIG_HOME:-~/.config}/systemd/user`, first line = `GSG_TIMER_MARKER`; install overwrites and uninstall removes only files carrying it. `systemctl` is read by `type -P` in `lib/install.sh` only (`test_systemctl_is_looked_up_only_in_lib_install_sh`) and stored as `SYSTEMCTL_BIN` in the settings (written only when a timer is wanted or recorded; `load_settings` unsets an inherited one). State key `timer_installed=yes|no` is optional (absent = no); `state_write` takes it as 8th argument. A plain install over `timer_installed=yes` keeps the timer RECORDED but never enables it and never needs `systemctl` (`install_refresh_timer_units`: rewrites a unit only when it is ours and its text changed, prints a `daemon-reload` hint; `install_prepare_timer` keeps `SYSTEMCTL_BIN` from the old settings when `PATH` has none); only `--with-timer` sets `INSTALL_TIMER_ENABLE`. The unit carries `TimeoutStartSec=1h`, `Environment="PATH=<dir of the git found first>:/usr/local/bin:/usr/bin:/bin"` (each directory once, `timer_unit_path`) because the user manager's PATH differs, and one `Environment=` line for each of `XDG_DATA_HOME`, `XDG_STATE_HOME`, `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL` that was set when install ran (`GSG_TIMER_ENV_NAMES`; the user manager does not pass the login environment on); paths with `"`, `\`, `%`, `$` or control characters are refused instead of escaped.

To bump, read the new fingerprint the same way inside a container and compare it with Launchpad's page for the PPA before changing the constant.
- **Install checks every prerequisite first** (`install_check_prerequisites`, E2E-1): git (missing or old), jq, setsid, timeout, curl only when a scanner must be downloaded (`install_downloads_needed`; an unresolved `timeout` counts as "needed"), systemctl only with `--with-timer` (`install_find_systemctl`). Each keeps its own message and hint; more than one adds `N prerequisites are missing; install refused, nothing was changed`. `install_resolve_bins` returns the number of failures.
- **awk's own error text.** mawk exits 2 with `close failed on file "<path>"` (and gawk with a redirect error) before `extract.awk` can look at `close()`, and the path may hold control characters. `extract_added_lines` therefore pipes awk's stderr through `_extract_clean_stderr` (one line, every byte outside space..tilde becomes `?`) and returns awk's own status from `PIPESTATUS`; `2>&1` loses nothing because `extract.awk` prints only to files and `/dev/stderr`. Test: `check_awk_error_with` (a directory named like the added file with ESC and TAB in its name); under mawk it runs in the container.
- **A redirection that fails is reported by bash before `2>/dev/null` applies.** `mapfile ... <"$f" 2>/dev/null` prints `line N: f: No such file`; write `{ mapfile ... <"$f"; } 2>/dev/null`. Done in `install_os_release_field` and `first_message`.
- **os-release is read as data everywhere.** `install_os_release_field FILE KEY` (first `KEY=` line, one pair of quotes removed, no expansion) serves `install_os_family`, `ubuntu-container.sh` (`os_field`) and `ubuntu-e2e.sh`; `test_the_container_script_reads_os_release_as_data` fails if any platform script sources `/etc/os-release`.
- **Doctor and Ctrl-C.** `timeout` (no `--foreground`) puts each git call in its own process group, so Ctrl-C in a terminal does not reach that git: doctor stops only when the current call ends, up to `DOCTOR_TIMEOUT_SECONDS` (30) plus the 5 s `-k` grace. Accepted: the call is bounded and leaves no process behind (`test_a_timed_out_doctor_run_leaves_no_process_behind`).
- **Credentials in a remote URL.** git strips `user:pass@` from the URL in its error messages, not a token placed in the URL path (`https://host/<token>/repo.git`). `exempt_head_blob` may therefore show that token in `EXEMPT_GIT_ERR` on the user's own stderr. It is the user's configuration printed to the user's terminal, so it stays; `exempt_head_blob` also keeps git's stderr in `<dest>.err` inside the hook's private work dir, which goes away with it.
- **Reviewer misreads in this round** (the relayed reviewer was wrong, the code stays): `awk -F: '$1 == "fpr" {print $10}'` is right for `gpg --with-colons` (field 10 holds the fingerprint of an `fpr` record); `lib/extract.awk` writes nothing to stdout, so `2>&1 |` into the sanitizer cannot swallow extracted lines; a process substitution for the stderr filter would race with the function's return.

## Review round 3 (story 04.01): what the fixes taught

- **No `containers.conf` layer is read** (H, the root cause). `PODMAN_ENV` in `tests/platform/ubuntu.sh` carries `CONTAINERS_CONF=<scratch HOME>/containers.conf`; containers.conf(5): "all system and user config files are ignored and only the specified config file will be loaded". The file is `[engine]` + `hooks_dir = ["<scratch HOME>/hooks.d"]` (an empty dir, created by the script; a scratch path holding `"` or `\` is refused because it would break the TOML string). Probed with real containers (user layer in the scratch home as the stand-in for `/etc`, which is never touched): the layer's `volumes` was visible without `CONTAINERS_CONF` and absent with it; `net.ipv4.ping_group_range` goes from the system default `0 0` to `65534 65534` and the container still runs; **OCI hook positive control**: a hook in a configured `hooks_dir` ran, the same setup with an empty `hooks_dir` ran nothing, so the hook trust decision is now a control. `CONTAINERS_CONF_OVERRIDE` is read last even with `CONTAINERS_CONF` set and is the only channel left; `env -i` drops it, and the tests use it as the "a layer got through" stand-in.
- **The empty user `mounts.conf` is still needed.** Under `CONTAINERS_CONF` a user `mounts.conf` mapping a scratch dir is honoured (marker visible), an empty one hides it, and `default_mounts_file` inside the `CONTAINERS_CONF` file does nothing for rootless (marker absent). `storage.conf`, `registries.conf` and `policy.json` are separate files `CONTAINERS_CONF` does not cover: a trust decision, said in `docs/platforms.md`.
- **Exact mount table + fstype** (`ISOLATION_MOUNT_RULES`, `MOUNTPOINT=FSTYPE`, `*` = any). Derived again under `CONTAINERS_CONF`: the same 33 mount points as round 2, stable over two runs (`/dev` tmpfs, `/dev/{full,null,random,tty,urandom,zero}` devtmpfs, `/dev/mqueue` mqueue, `/dev/pts` devpts, `/dev/shm` tmpfs, `/etc/{hosts,hostname,resolv.conf}` and `/run/.containerenv` tmpfs, `/proc` proc, `/proc/{asound,bus,fs,irq,sys,sysrq-trigger}` proc, `/proc/{acpi,scsi}` tmpfs, `/proc/{interrupts,kcore,keys,timer_list}` devtmpfs, `/sys` sysfs, `/sys/firmware` and `/sys/fs/selinux` tmpfs, `/sys/fs/cgroup` cgroup2). `/`, `/src` and `/run/podman-init` take any fstype (the host's). Three masked files other kernels add (`/proc/latency_stats`, `/proc/sched_debug`, `/proc/timer_stats`) were read from the podman 5.6.0 binary, not probed; their fstype `devtmpfs` is by analogy. A mount point seen twice is named `mounted more than once`; 500 lines is the bound. The fstype is the word after the lone `-` in `/proc/self/mountinfo` (proc(5): field 4 root, field 5 mount point; neither root nor the field-10 source is printed). a cgroup v1 host (`/sys/fs/cgroup` not cgroup2) aborts naming the mount point and its fstype: fail closed, adjust the table. The check rejects only extra, duplicate or wrong-fstype mount points, never a missing one, so a kernel without selinuxfs (or without `/sys/firmware`) passes.
- **`/dev` is listed recursively** (`find -mindepth 1 -maxdepth 4 -printf '%P\0'`, at most 500 entries, `wait "$!"` for find's status, rc 2 when a subdirectory cannot be read): 17 baseline entries (`core fd full mqueue null ptmx pts pts/ptmx random shm stderr stdin stdout tty urandom zero`) plus `pts/<digits>`. Under `shm`, `mqueue` and `pts` a stray is only counted (`shm/* (count 2)`): with `ipcns = host` those names are host IPC objects.
- **Host-namespace detection by inode, passed in by the launcher.** Counting `/sys/class/net` was rejected: pasta gives the container a copy of the host NIC (`ens18 lo`), so a one-NIC host cannot be told from `netns = host`. Instead `ubuntu.sh` reads its own `/proc/self/ns/{cgroup,ipc,net,pid,uts}` and passes `--host-ns NAME=ID` (arguments, never environment); `isolation_shared_namespaces` compares them with `/proc/1/ns` and prints only the name; a missing or non-numeric id, or an unreadable link, is rc 2 and fails the check. Probed with `netns`, `ipcns`, `utsns`, `cgroupns = host` (each named exactly); `pidns = host` is refused by podman under `--init`; `time` is shared by default and `user` would be shared by rootful podman, so neither is compared. `--image REF` carries the pinned reference into the summary (`image:` line) and the launcher's final line `PASS (image <ref>)`.
- **A `volumes` entry onto `/src` is a no-op**, not a bypass: the command-line `-v copy:/src:ro,Z` wins over a config `volumes` entry for the same target (probe: copy file visible, host file not, one mount entry).
- **Bypass battery** (real containers, harness copies of the launcher in the scratchpad, three variants each: layer as user layer with `CONTAINERS_CONF` removed = control, launcher as shipped, layer through `CONTAINERS_CONF_OVERRIDE`): volumes onto `/dev/shm`, `/dev/shm/x`, `/etc/hosts`, `/run/.containerenv`, `/dev/mqueue` (also with `:ro`), devices onto `/dev/shm/gsgfuse`, `ipcns = host`, `netns = host`: control and override abort naming mount points, fstypes, `shm/* (count N)` and the namespace; the shipped launcher ignores the layer and the check passes. The OCI hook ran in control and override and not in the shipped launcher: the in-container check cannot see a hook, `CONTAINERS_CONF` is the control. Residual: a host `tmpfs` file mounted over `/etc/hosts` would show fstype `tmpfs`; it needs a layer or a CLI flag, and neither exists now.
- **`install_git_ppa` returns 2 when `ppa_disable` fails** (M1 gap) and `obtain_git` then records one failure and stops: no `install_git_source`, whose root `apt-get install` would trust a PPA that may still be enabled. `ppa_disable` also removes `git-core-ubuntu-ppa-*.list`. Stub tests: `PPA_STUB_ENV` knobs (`STUB_LOCK` copies the `.sources` file first and then makes the directory read-only, so the later removal fails; `STUB_ADD_RC`; `STUB_UPDATE_FAIL_PPA` / `STUB_UPDATE_FAIL_CLEAN` fail `apt-get update` with or without the PPA present). The lock test needs a non-root user (root ignores mode 555); the container suite runs as `gsguser`.
- **The hook's message after an awk write failure** says `extracting the added lines of the staged diff failed (...)`; the sanitized awk line printed before it stays. Test: a path with a 300-character component staged through `update-index --cacheinfo` (the index takes it, the file system does not), `test_an_extraction_write_failure_blocks_with_a_message_about_extraction_and_keeps_the_awk_line`.

The comment lint rejects ` that `, ` so `, ` which `, `: ` and more than three coded comment lines in a row.

## Review round 4 (story 04.01): what the fixes taught

- **`/sys/devices/virtual/powercap=tmpfs` is an optional entry of `ISOLATION_MOUNT_RULES`** (M1). It is one of podman 5.6.0's default masked paths (the string is in the binary) and exists only where `intel_rapl` does, so the 33-entry baseline from this VM lacked it and a physical Intel/AMD host would have aborted with `mount points outside the allow-list: /sys/devices/virtual/powercap`. Test: `test_the_mount_check_accepts_the_optional_masked_paths_other_kernels_add` (any other fstype is named).
- **The rest of podman's default list was already in the table.** Read from the binary (`strings $(command -v podman) | grep -oE '/(proc|sys)/[A-Za-z0-9_./-]+'`, the Go strings run together, so read them by name): masked `/proc/acpi /proc/interrupts /proc/kcore /proc/keys /proc/latency_stats /proc/sched_debug /proc/scsi /proc/timer_list /proc/timer_stats /sys/firmware /sys/fs/selinux /sys/devices/virtual/powercap`, read-only `/proc/asound /proc/bus /proc/fs /proc/irq /proc/sys /proc/sysrq-trigger` (fstype `proc`); only powercap was missing (re-derived independently in review round 5). powercap exists wherever a powercap driver is loaded (RAPL on physical Intel/AMD), not only `intel_rapl`.
- **Probing a mask needs a path that exists.** crun skips a masked path that is absent, so `--security-opt mask=/sys/devices/virtual/powercap` is a no-op on a host without `intel_rapl` (no mount appeared, rc 0 as before), and `--tmpfs` at that path fails (`crun: mkdir ... Permission denied`, sysfs is not writable). Real proof used an existing `/sys/devices/virtual/misc`: the mask shows as a `tmpfs` mount at exactly that mount point, the shipped table names it, and the table with that one entry accepts it. A mask of a non-allowed path (`--security-opt mask=/sys/dev/block`) still fails with the mount point named.
- **Docs fixed:** the seccomp profile is root-owned `/etc/containers/seccomp.json` when present, else `/usr/share/containers/seccomp.json` (the one `podman info` reports here; both strings are in the binary, the precedence is from containers/common, not probed), which `CONTAINERS_CONF` does not cover (trusted file, not a podman built-in); podman is "the podman found first on your `PATH`" because the launcher passes the caller's `PATH` (not pinned to `/usr/bin/podman`); the mount table is host-specific (`docs/platforms.md` says how to adjust it).

## Conventions

- Comments follow `~/.claude/coded-comments` (`# ^ tag clause`), kept sparse. `set -u`; check every return value; loops are bounded; shellcheck reports nothing (info included), directives only where the code is intentional.
- Fake credential tests never print the fake value; assert absence with `no_leak`.
- Do not modify anything under `~/.config/git/` from this project's tests or code.

# Code of conduct

git-secret-guard guards commits for people who rely on it, so the work is reviewed strictly. The people doing it are treated with
respect. This page says what that means here, and what to do when it does not happen.

## Where it applies

Everywhere the project is discussed or worked on: issues, pull requests, review comments, commit messages, security advisories, and
any other place where someone speaks or acts for the project.

It applies to everyone who takes part: maintainers, contributors, people who report a problem, and AI coding agents. An agent acts for
a person, and that person answers for what the agent posts, as for anything else submitted under their name
([sign-off](CONTRIBUTING.md#sign-your-commits-dco), [working rules for agents](docs/agents.md)).

## What we expect

- **Criticise the work, not the person.** Say what is wrong and show it: a failing test, a log, the line of code. A claim without
  evidence is a question, and is asked as one.
- **Take a strict review as part of the job.** A pull request is held to the [rules for changes](CONTRIBUTING.md#rules-for-changes):
  a test for every behaviour, documentation for what a user sees. A change that is sent back, a request for a test or a declined
  feature is not a conduct problem, and a reviewer asks for it without talking down to the author.
- **Be patient with a first report.** Someone who left out the platform or the `status` output is asked for it, plainly.
- **Say what you did not check.** "Not run on macOS" is useful to the next person; a result that was not measured is not reported as one.
- **Keep private things private.** Never post a real credential, not even a revoked one ([reporting](CONTRIBUTING.md#reporting)),
  and nothing that identifies another person, their machines or their accounts without their consent
  ([no private details](docs/agents.md#no-private-details-in-files-or-on-github)). An issue, a comment and a commit message are public
  and stay public.
- **Leave other people's work alone.** A branch, a pull request, a work directory or a running job that is not yours is not yours to
  close, overwrite or stop.

## What we do not accept

- Insults, personal attacks, mockery, and comments that demean a person or a group, whatever the reason given.
- Harassment of any kind: sexual language or attention, threats, following someone from one thread or one site to another, or going
  on after being asked to stop.
- Publishing someone's private information, or a secret that is theirs.
- Disrupting the work on purpose: flooding issues or pull requests, reopening a settled question again and again without new facts,
  or sending changes nobody has read (written by a tool or not) for others to sort out.
- Disclosing a vulnerability in public before the maintainers could act on it: [SECURITY.md](SECURITY.md) is the path.

## Reporting a problem

Write privately to a maintainer. The maintainers are named in the [README](README.md#license-and-maintainers); use the contact
details on a maintainer's GitHub profile. If the problem is with a maintainer, write to another one, or report it to GitHub as
described below.

- Do not open a public issue about a person's conduct, and do not use the vulnerability reporting form for it.
- Say what happened, where (a link is best) and when. Do not copy private information into the report beyond what is needed.
- Content on GitHub that is abusive can also be reported to GitHub itself, with the "Report content" entry of the comment's menu.

A report is kept confidential: the person who made it is not named to the person it is about without their agreement.

## What the maintainers do

The maintainers read every report, aim to acknowledge it within 5 business days, and decide what follows in proportion to what
happened:

- a private note that asks for a change in behaviour, or for a comment to be edited;
- hiding or deleting a comment, or locking a thread;
- a block from the repository for a time, or for good.

The same holds for a maintainer. A decision is explained to the person it concerns, and they may answer it once, in private.
